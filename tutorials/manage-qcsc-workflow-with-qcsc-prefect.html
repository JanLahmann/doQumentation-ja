QCSC-Prefect で量子中心スーパーコンピューティングのワークフローを管理する

使用量の目安: IBM Quantum® Heron r2 プロセッサー上で QPU 時間30秒。この目安にはキューの待ち時間と古典処理は含まれません。実行時間は異なる場合があります。

学習目標​

  • Prefect Cloud で、Qiskit pattern の各ステージにつき 1 つのタスクとして、クォンタム・セントリック・スーパーコンピューティング (QCSC) ワークフローをトレースします。

  • ロールごとにワークフローを構成します。実行パラメーターは Prefect Cloud の実行フォームで、ハイ・パフォーマンス・コンピューティング (HPC) と量子処理装置 (QPU) の設定は Prefect ブロックで指定します。

  • 失敗した実行を、QPU ジョブを繰り返さずに再開し、ある実行のサンプルを新しい実行で再利用します。

前提条件​

  • Slurm クラスターでの QCSC-Prefect のセットアップ。Slurm ログインノード、Python 環境、IBM Quantum の認証情報を準備します。

  • 化学ハミルトニアンのサンプルベース量子対角化。アルゴリズムを説明しています。

背景​

QCSC ワークフローは、QPU と HPC システムを 1 つのマシンとして動かします。 QCSC-Prefect は、QCSC ワークフローを Prefect 上で実行し、トレース可能、構成可能、再開可能にします。

このチュートリアルでは、N2_22​ 分子のサンプルベース量子対角化 (SQD) を使って、これらの機能を示します。Quantum Resource Management Interface (QRMI) が Slurm ジョブの中で回路をサンプリングします。 Fulqrum 固有値ソルバーが、サンプリングされた 部分空間を、さらに多くの Slurm ジョブで対角化します。1 つの Prefect Cloud デプロイメントが、その両方を実行します。

QCSC-Prefect は、次のプロジェクトのように、大規模な QCSC ワークロードも実行します。

  • 12,000 個を超える原子を持つタンパク質・リガンド複合体の研究で、QCSC-Prefect が使われました。この研究では、2 台の 156 量子ビットの IBM Quantum プロセッサーで、最大 94 量子ビットを使って量子埋め込みフラグメントをサンプリングし、フラグメントの部分空間を、富岳、Miyabi-G、ROQUO の スーパーコンピューターで対角化しました [1]。

  • 鉄・硫黄クラスターの研究では、36 軌道 (72 量子ビット)、部分空間の次元が最大 3×10103 \times 10^{10}3×1010 の拡張 QCSC-Prefect SQD ワークフローを、富岳、Miyabi、 ROQUO のスーパーコンピューターで実行しました [2]。

QCSC ワークフローの課題​

SQD ワークフローは、QCSC ワークロードの典型です。QCSC-Prefect は、次の表のように、その各課題に 1 つの機能で対応します。

課題QCSC-Prefect の機能
複数のリソースにまたがります。1 つの Slurm ジョブが QPU を確保し、その後、多数の Slurm ジョブが部分空間を何ラウンドにもわたって対角化します。トレース可能なワークフロー
異なるレベル (科学、回路、クラスター) に多くのパラメーターがあり、認証情報はそのいずれにも含めてはいけません。構成可能なパラメーター
長時間かかり、ウォールタイム制限、ノード障害、長い QPU キューなど、どこでも失敗する可能性があります。対策しないと、後半の失敗で QPU でのサンプリングをやり直すことになります。再開可能な実行

QCSC-Prefect での Qiskit pattern のステップごとの解説の各ステップの最後には、QCSC-Prefect がそのステージをどのようにトレース、構成、再開するかを示すボックスがあります。

トレース可能なワークフロー​

Prefect のフローは、タスクで構成された Python 関数です。QCSC-Prefect は、Qiskit pattern の各ステージ (Map、Optimize、Execute、Postprocess) を 1 つのタスクにします。実行ごとに、Prefect Cloud は次の情報を表示します。

  • タスクグラフ。あるタスクが結果を別のタスクに渡す箇所には矢印が表示されます。

  • 各タスクの状態、入力、ログ、実行時間。ステージタグ map、optimize、execute、post-process で絞り込めます。

  • アーティファクト。タスクが公開するテーブルやリンクで、たとえばサンプルの取得元や各部分空間のエネルギーなどです。

ワークフローホストは、作業の送信と監視だけを行います。計算負荷の高い作業は、次の画像のように Slurm ジョブとして実行されます。

構成可能なパラメーター​

QCSC-Prefect は、次の表のように、設定の種類ごとに専用の場所を用意しています。

種類例変更頻度保存場所
実行パラメーター分子、ショット数、部分空間の次元実行ごとPrefect Cloud の実行フォーム (ステージごとにグループ化)
ブロックパーティション、ウォールタイム、スレッド数、実行ファイルのパス、QPU リソースクラスターごとPrefect ブロック (1 回だけ作成)
認証情報Prefect API キー、IBM Quantum API キーまれにワークフローホストでの Prefect Cloud ログインと、クラスターでの QRMI (qcsc-qrmi login)。どちらもセットアップガイドで設定します

ブロックは、次の表の 3 つの層で各ジョブを記述します。

ブロック指定する内容内容
CommandBlock何を実行するか実行ファイルとそのデフォルト引数
ExecutionProfileBlockどのように実行するかノード、スレッド、ウォールタイム、ランチャー、モジュール、環境
HPCProfileBlockどこで実行するかスケジューラー、パーティション、アカウント、そのシステム上の各実行ファイルのパス

フローは実行時にブロックを名前で読み込むため、ブロックを変更しても、フローとその実行 パラメーターは変わりません。

再開可能な実行​

Prefect は、最初の 3 つのステージの結果をフロー実行とともに保存します。後のタスクが 失敗した場合、フロー実行の Retry は保存された結果を再利用し、失敗した部分だけを実行します。次の 画像を参照してください。

Execute ステージがサンプルの保存場所を記録するため、新しい実行は、サンプリングする代わりに以前の実行のサンプルを読み込むこともできます。

SQD の概要​

SQD は、結合クラスター一重・二重励起 (CCSD) 振幅から構築した局所ユニタリー・クラスター Jastrow (LUCJ) 回路からビット列をサンプリングし、ノイズで破損した ビット列を修正し (configuration recovery)、サンプリングされた配置が張る部分空間で ハミルトニアンを対角化します [3]。 SQD チュートリアルでアルゴリズムを説明しています。QCSC-Prefect では、SQD は フロー sqd であり、次のタスクグラフを持ちます。

ステージタスク別のタスクからの入力
Mapcompute_molecular_integralsなし
Optimizeget_lucj_paramsMap からの積分
Executequantum_sampling (内部に build_lucj_circuit を含む)Optimize からの LUCJ パラメーター
Postprocesssqd_loopMap からの積分と Execute からのサンプル

実行がサンプルを再利用する場合、load_qrmi_result (IBM Quantum Platform のサンプルの場合は load_runtime_job) が get_lucj_params と quantum_sampling の両方を置き換えるため、実行に Optimize タスクはありません。ランダムモード (Quantum Source を random に設定) では、Optimize も Execute もタスクがなく、Map が sqd_loop に直接入力します。

例は、6-31G 基底、結合長 1.1 A˚\AAA˚ の N2_22​ で、2 つの 1s 内殻 軌道は凍結します。これにより、5 個の α\alphaα 電子と 5 個の β\betaβ 電子を持つ 16 個の空間軌道が残り、 32 量子ビットの回路になります。

要件​

このノートブックのコードセルを実行するには、ノートブックのカーネルに次のパッケージをインストールしてください。

  • Qiskit SDK v2.0 以降、および可視化サポート。

  • Qiskit Runtime v0.40 以降 (pip install qiskit-ibm-runtime)。

  • SQD Qiskit アドオン v0.14 以降 (pip install qiskit-addon-sqd)。

  • ffsim v0.0.75 以降 (pip install ffsim)。

  • Fulqrum v1.0 以降 (Fulqrum のインストールガイドを参照)。

このノートブックのステップ 3 は Qiskit Runtime でサンプリングするため、ログイン認証情報の保存で説明されているとおり、ノートブックを実行するコンピューターに保存された IBM Quantum アカウントが必要です。

備考

QCSC-Prefect ワークフローは、このノートブックではなく、Slurm が管理するクラスターで実行されます。実行する前に、Slurm クラスターでの QCSC-Prefect のセットアップを 完了してください。これにより、次の項目が用意されます。

  • $QCSC_PREFECT (~/qcsc-prefect) にある QCSC-Prefect のチェックアウトと、$QCSC_WORK_DIR (/shared/work/qcsc-prefect) にある作業ディレクトリ。どちらも、計算ノードが共有するストレージ上にあります。

  • ワークフローホストである Slurm ログインノードにある、QCSC-Prefect パッケージを含む環境 ~/venv/qcsc-host と、Prefect Cloud ログイン。

  • qcsc-qrmi login で保存された IBM Quantum の認証情報と、QRMI とその SPANK プラグインを備えたクラスター上の qrmi-runtime ブロック。

  • 計算ノードにある、QRMI、その task_runner、qcsc-prefect-qiskit を含む環境 ~/venv/qcsc-node。

次のステップを 1 回だけ実行してください。各ステップには、実行するノードが示されています。

ワークフローホストに SQD ワークフローをインストールする​

セットアップガイドの変数を設定し、~/venv/qcsc-host を有効化して、SQD ワークフローと Fulqrum 統合をインストールします。

# Run in a terminal on the workflow host.
# Optional if your ~/.bashrc sets the two variables
export QCSC_PREFECT="$HOME/qcsc-prefect"
export QCSC_WORK_DIR="/shared/work/qcsc-prefect"

source ~/venv/qcsc-host/bin/activate
cd "$QCSC_PREFECT"
uv pip install --no-deps -e packages/qcsc-prefect-fulqrum
uv pip install -e algorithms/qcsc_workflow_utility
uv pip install -e algorithms/open_loop/sqd
which sqd-create-blocks sqd-deploy

計算ノードに Fulqrum ソルバーをインストールする​

計算ノードでシェルを開きます。srun は、ワークフローホストのシェルの変数を 計算ノードに渡します。

# Run in a terminal on the workflow host.
srun -N1 --pty bash

QRMI ワーカーは、Qiskit のみをインポートする SQD トランスパイルフックを使って、計算ノード上で回路をトランスパイルします。フックを ~/venv/qcsc-node に追加し、インポートを確認します。インポートが成功すると、 python コマンドは何も出力しません。

# Run in the shell on the compute node.
source ~/venv/qcsc-node/bin/activate
cd "$QCSC_PREFECT"
uv pip install --no-deps -e algorithms/open_loop/sqd
python -c "import qrmi, qcsc_prefect.integrations.qiskit.qrmi.worker, sqd_common.transpile"

Fulqrum と qcsc-fulqrum-solve を、専用の環境 packages/qcsc-prefect-fulqrum/native/fulqrum にビルドします。ビルドには OpenMP 対応の C++ コンパイラーが必要です。 FULQRUM_WITH_PRIMME=1 を指定すると PRIMME 固有値ソルバーもビルドされ、その場合は C コンパイラー、Python ヘッダー、pkg-config、.pc ファイルを持つ BLAS および LAPACK ライブラリが必要です。

# Run in the shell on the compute node.
cd "$QCSC_PREFECT"
FULQRUM_WITH_PRIMME=1 bash packages/qcsc-prefect-fulqrum/native/build_fulqrum.sh
realpath packages/qcsc-prefect-fulqrum/native/fulqrum/bin/qcsc-fulqrum-solve
exit

ソルバーブロックがこのパスを参照するため、出力されたパスを記録してください。exit でワークフロー ホストに戻ります。ビルドオプションについては、 Fulqrum integration を参照してください。

ワークフローホストで Prefect ブロックを構成して作成する​

サンプル構成をコピーします。

# Run in a terminal on the workflow host.
cd "$QCSC_PREFECT"
cp algorithms/open_loop/sqd/sqd_blocks.example.toml \
   algorithms/open_loop/sqd/sqd_blocks.toml

次の表のように、sqd_blocks.toml の先頭にある設定を編集します。

パラメーター例説明
python_executable"~/venv/qcsc-node/bin/python"~/venv/qcsc-node の Python。計算ノードに Fulqrum ソルバーをインストールするのフックを含みます
profile"slurm"システムプロファイル。slurm、slurm-gpu、miyabi、miyabi-gpu、fugaku、または独自ファイルへのパスのいずれかです
solver"fulqrum"部分空間の対角化ソルバー。fulqrum、sbd、dice のいずれかです
queue"normal"ソルバージョブの Slurm パーティション
project"my-account"任意の Slurm アカウント (#SBATCH --account)

ファイルを編集するときは、次の点に注意してください。

  • ファイルは環境変数を展開しないため、パスはすべて書き出してください。~ 文字は使用できます。python_executable などのトップレベルのキーはすべて、最初のテーブルヘッダーより前に置いてください。

  • qrmi-runtime ブロックがインスタンスと QPU を提供するため、[qrmi] テーブルは変更する必要がありません。バックエンドを上書きする場合にのみ resource を設定します。認証情報は このファイルではなく qrmi_config.json に残ります。

  • slurm プロファイルは、汎用 Slurm クラスターのスケジューラーとリソースの設定を保持しており、ファイル内のどのキーでも上書きできます。コメントアウトされた [sqd_advanced] テーブルは sqd-advanced-settings ブロックを設定し、コメントアウトされた [advanced] テーブルはブロック名とタイムアウトを設定し、 各ソルバーのテーブルはそのチューニングを保持します。ソルバージョブのノード、ランク、スレッドを選ぶには、 Size the SQD diagonalization for your HPC resources を参照してください。

  • QRMI ジョブと各ソルバージョブのウォールタイムは 12 時間 (#SBATCH --time) で、フローは各ジョブを最大 13 時間 (timeout_seconds = 46800) 待ちます。ウォールタイムを変更するには、ソルバージョブの場合はファイルの先頭で walltime を設定し、QRMI ジョブの場合は [qrmi] テーブルで設定します。 たとえば walltime = "02:00:00" です。ウォールタイムを短くすると、混雑したクラスターでも早く開始できる場合があります。

ブロックを作成します。

# Run in a terminal on the workflow host.
sqd-create-blocks --config algorithms/open_loop/sqd/sqd_blocks.toml

このコマンドは、次の表のブロックを保存します。

ブロックロール
ソルバーセット (cmd-sqd-fulqrum-solver、exec-sqd-fulqrum-slurm、hpc-slurm-sqd-fulqrum)ソルバージョブの 3 つの層
QRMI セット (cmd-sqd-qrmi、exec-sqd-qrmi、hpc-slurm-sqd-qrmi)QPU を要求する QRMI Sampler ジョブの 3 つの層
qrmi-runtimeQRMI セットの Slurm 設定と、qcsc-qrmi login で設定したインスタンスおよびバックエンドを持つ QrmiRuntimeBlock (scheduler = "slurm")。実行フォームのデフォルトの QRMI Runtime Block です
sqd-fulqrum-solverソルバーセットをラップし、固有値ソルバーの設定を保持する FulqrumSolverJob
sqd-advanced-settingsすべての実行の Solver Block (fulqrum_solver_job/sqd-fulqrum-solver)、CCSD の反復回数 (CCSD Restarts、デフォルトは 10)、リセット緩和、トランスパイラーの設定

何も保存せずに解決済みの設定を出力するには、--dry-run を追加します。prefect block ls と Prefect Cloud の Blocks ページにブロックが一覧表示されます。次の画像を参照してください。

ワークフローホストにワークフローをデプロイする​

sqd-deploy は、ワークフローホストからフローを提供し、Prefect Cloud で開始した実行を受け取るため、ワークフローを実行している間はターミナルを開いたままにしてください。次のコマンドは、 開始のたびに $QCSC_WORK_DIR/logs/deploy 以下に新しいログファイルへ出力も書き込みます。 ファイル名は UTC の開始時刻にちなんで付けられ、たとえば sqd-deploy-20261109T051530Z.log です。

# Run in a terminal on the workflow host.
mkdir -p "$QCSC_WORK_DIR/logs/deploy"
sqd-deploy 2>&1 | tee "$QCSC_WORK_DIR/logs/deploy/sqd-deploy-$(date -u +%Y%m%dT%H%M%SZ).log"

出力にフロー sqd が提供されていると表示されると、デプロイメントは Prefect Cloud の Deployments に表示されます。提供を停止するには Ctrl+C を押します。

QCSC-Prefect での Qiskit pattern のステップごとの解説​

次のステップでは、Prefect を使わずに、PySCF、ffsim、Qiskit、Qiskit Runtime、qiskit-addon-sqd を使って、このノートブックで 4 つのステージを計算します。各計算の詳細については、SQD チュートリアルを参照してください。

ステップ 1: 古典的な入力を量子問題にマッピングする​

Map ステージ (ワークフローではタスク compute_molecular_integrals) は、分子を以降のすべてのステージへの入力に変換します。制限付きハートリー・フォック (RHF) が分子軌道を与え、活性空間積分は凍結された 2 つの 1s 内殻を除きます。CCSD はアンザッツの t2t_2t2​ 振幅を与え、その密度行列は configuration recovery の出発点となる軌道占有数を与えます。CCSD は CCSD_MAXITER 回反復し、毎回前の振幅から始めるため、結果は最初の反復の DIIS 履歴に依存しません。このノートブックでは 4 回の反復を使い、ワークフローでは 10 回を使います。

ATOM = "N 0 0 0; N 0 0 1.1"
BASIS = "6-31g"
N_FROZEN = 2
CCSD_MAXITER = 4

mol = pyscf.gto.M(atom=ATOM, basis=BASIS, symmetry=False, verbose=0)
mf = scf.RHF(mol).run()
norb = mol.nao_nr() - N_FROZEN
nelec = (mol.nelec[0] - N_FROZEN, mol.nelec[1] - N_FROZEN)

# Active-space Hamiltonian with the 1s cores frozen
cas = mcscf.CASCI(mf, ncas=norb, nelecas=nelec)
one_body_tensor, core_energy = cas.get_h1eff()
two_body_tensor = ao2mo.restore(1, cas.get_h2eff(), norb)

# CCSD, iterated from the previous amplitudes
ccsd = cc.CCSD(mf, frozen=N_FROZEN)
eris = ccsd.ao2mo()
ccsd.kernel(eris=eris)
for _ in range(CCSD_MAXITER - 1):
    ccsd.kernel(ccsd.t1, ccsd.t2, eris=eris)
t2 = ccsd.t2

occupancies = np.diag(ccsd.make_rdm1())[N_FROZEN:] / 2
initial_occupancies = (occupancies, occupancies)

print(f"norb = {norb}, nelec = {nelec}")
print(f"E(RHF)  = {mf.e_tot:.8f} Ha")
print(f"E(CCSD) = {ccsd.e_tot:.8f} Ha")
norb = 16, nelec = (5, 5)
E(RHF)  = -108.86761837 Ha
E(CCSD) = -109.09392115 Ha
QCSC-Prefect がこのステップを管理する方法

トレース: タスク compute_molecular_integrals にはタグ map が付いています。その結果は get_lucj_params と sqd_loop に渡されるため、グラフではそこから 2 本の矢印が出ます。タスクのログには PySCF の出力が表示されます。

構成: 実行フォームの Molecule グループで、FCIDUMP ファイル、または形状と基底によって問題を選択します。このワークフローは、すでに内殻が凍結されている algorithms/open_loop/sqd/data/n2_631g_fc.fcidump を読み込みます。CCSD の反復回数 (CCSD Restarts、デフォルトは 10) は、sqd-advanced-settings ブロックにあります。

再開: 結果は永続化されている (compressed/json) ため、Retry は PySCF を再実行する代わりに結果を読み込みます。

ステップ 2: 量子ハードウェアでの実行に向けて問題を最適化する​

Optimize ステージ (ワークフローではタスク get_lucj_params) は、回路が存在する前に、アンザッツを QPU に合わせます。ffsim は、ヘビーヘックス格子が SWAP ゲートなしで実行できる相互作用だけを使って、t2t_2t2​ から LUCJ 演算子を構築します。これらは、隣接する軌道の同一スピン対と、4 軌道ごとの逆スピン対で、ヘビーヘックス (Heron) プロセッサーでは最大 5 つです。その後、ffsim は演算子を圧縮し (optimize=True、ワークフローではデフォルトで有効)、1 つの層で t2t_2t2​ をより正確に再現します。

N_REPS = 1

pairs_aa = [(p, p + 1) for p in range(norb - 1)]
pairs_ab = [(p, p) for p in range(0, norb, 4)][:5]

lucj_op = ffsim.UCJOpSpinBalanced.from_t_amplitudes(
    t2,
    n_reps=N_REPS,
    interaction_pairs=(pairs_aa, pairs_ab),
    optimize=True,
    options={"maxiter": 50},
)
n_params = ffsim.UCJOpSpinBalanced.n_params(
    norb, N_REPS, interaction_pairs=(pairs_aa, pairs_ab)
)

print(f"Opposite-spin pairs: {pairs_ab}")
print(f"Ansatz parameters: {n_params}")
Opposite-spin pairs: [(0, 0), (4, 4), (8, 8), (12, 12)]
Ansatz parameters: 275
QCSC-Prefect がこのステップを管理する方法

トレース: タスク get_lucj_params にはタグ optimize が付いています。その結果には回路に必要なすべてが含まれているため、そこから quantum_sampling へ 1 本の矢印が伸びます。

構成: 実行フォームの Circuit グループで、LUCJ の層数、圧縮とその反復回数の上限、相互作用の対を決める QPU Topology (heavy-hex または square) を設定します。sqd-advanced-settings ブロックには、Execute ステージが使うリセット緩和とトランスパイラーの設定 (最適化レベルと SABRE レイアウト探索) があります。

再開: 結果は永続化されている (compressed/pickle) ため、実行を再試行しても、長い圧縮は 1 回しか実行されません。

ステップ 3: Qiskit プリミティブを使って実行する​

Execute ステージ (ワークフローではタスク quantum_sampling) は、回路 (ハートリー・フォック状態、LUCJ 演算子、測定) を構築し、 QPU 向けにトランスパイルして、サンプリングします。ffsim の PRE_INIT パスはトランスパイラーで最初に実行され、 ffsim のゲートを効率的なネイティブゲート列に変換します。このノートブックは ibm_fez 上の Qiskit Runtime でサンプリングします。ibm_fez は、お使いのインスタンスが 利用できるバックエンドに置き換えてください。ワークフローは代わりに、QPU を確保する Slurm ジョブの中で QRMI を使ってサンプリングします。

service = QiskitRuntimeService()
backend = service.backend("ibm_fez")

circuit.append(ffsim.qiskit.PrepareHartreeFockJW(norb, nelec), qreg)
circuit.append(ffsim.qiskit.UCJOpSpinBalancedJW(lucj_op), qreg)
circuit.measure(qreg, circuit.cregs[0])

pass_manager = generate_preset_pass_manager(
    optimization_level=3, target=backend.target, seed_transpiler=24
)
pass_manager.pre_init = ffsim.qiskit.PRE_INIT
isa_circuit = pass_manager.run(circuit)
print(f"Backend: {backend.name}, ISA circuit depth: {isa_circuit.depth()}")

random_bool_array = generate_bit_array_uniform(
    SHOTS, 2 * norb, rand_seed=24
).to_bool_array()

def correct_electron_fraction(bool_array):
    """Fraction of the bitstrings with the correct numbers of alpha and beta electrons."""
    # The right half of each bitstring is alpha, the left half is beta.
    n_alpha, n_beta = nelec
    valid = (bool_array[:, norb:].sum(axis=1) == n_alpha) & (
        bool_array[:, :norb].sum(axis=1) == n_beta
    )
    return valid.mean()

QCSC-Prefect がこのステップを管理する方法

トレース: タスク quantum_sampling にはタグ execute が付いており、タスク build_lucj_circuit はその内部で実行されます。ワークフローホストは回路を準備し、QPU を要求する Slurm ジョブを送信します。計算ノードでは、SPANK プラグインが QPU セッションを開き、 QRMI ワーカーが回路をトランスパイルしてサンプリングします。 タスクのログには、Slurm ジョブのウォールタイム、トランスパイル後の回路の 2 量子ビット深さ、 そしてサンプリング完了時には IBM Quantum のジョブ ID と QPU の実行時間が表示されます。

構成: 実行フォームの Sampling グループで、ショット数とサンプルの取得元を設定します。取得元は、qrmi-runtime ブロック、以前の実行のジョブ、またはランダムなビット列です。 QRMI ブロックは、Sampler ジョブをどこで、どのように実行するかを保持し、認証情報は クラスターに残ります。

再開: サンプルは永続化されている (compressed/pickle) ため、Retry は新しい QPU ジョブを送信しません。sqd-sampling-source アーティファクトにサンプルの保存場所が記録されるため、新しい実行はそれらを再利用できます。 オプション: ワークフローの再開と再利用を参照してください。

Execute が回路を構築してトランスパイルする理由

QRMI ワーカーは、QPU の現在の Target に対して計算ノード上で回路をトランスパイルするため、QRMI Runtime がトランスパイルを担当します。この分担は、量子低密度パリティ検査 (LDPC) 誤り訂正回路のトランスパイルが重い処理となる、フォールトトレラントな QCSC システムへの準備です。ワークフローは、回路ではなく回路パラメーターをキャッシュします。 Map と Optimize が回路を設計します。Map は CCSD 振幅を計算し、Optimize は ffsim.UCJOpSpinBalanced.from_t_amplitudes(optimize=True) で LUCJ 演算子を圧縮します。これは、現在の QPU でのトランスパイルより 時間がかかることがあります。build_lucj_circuit とトランスパイラーは、 これらのパラメーターを ISA 回路にエンコードするだけです。この分担は従来の Qiskit pattern とは異なり、QCSC システムにおける Qiskit pattern の姿を示唆しています。

ステップ 4: 後処理を行い、望ましい古典形式で結果を返す​

Postprocess ステージ (ワークフローではタスク sqd_loop) は、自己無撞着な configuration recovery を実行します。各ラウンドでは、現在の軌道占有数でサンプリングされたビット列を修正し、複数のバッチの配置でハミルトニアンを対角化し、最良の結果から占有数を更新します。次の セルは、同じ設定で両方のサンプルセットに対して diagonalize_fermionic_hamiltonian を実行します。部分空間の次元は、ワークフローの 1,000,000 行列式 (スピンごとに 1,000 ストリング) です。 ノートブックでは 1 ラウンドあたり 2 バッチで 10 ラウンドを使い、ワークフローでは 4 バッチで 5 ラウンドを使います。ワークフローと同様に、Fulqrum が各部分空間を対角化します。 sci_solver_from_integrals は Fulqrum ハミルトニアンを 1 回だけ構築し、関数がバッチごとに呼び出す sci_solver を返します。SQD チュートリアルと同様に、TrimPolicy が、バッチの最も重い ストリングを 1 つの部分空間にまとめて対角化します。carryover_threshold を超えるストリングのうち、このポリシーは最も重い半分 (carryover_ratio=0.5) を次の ラウンドに引き継ぎます。これはワークフローの Carryover Fraction と同じです。

SUBSPACE_DIM = 1_000_000
NUM_BATCHES = 2
MAX_ITERATIONS = 10

policy = TrimPolicy(
    trim_ratio=0.8,
    carryover_threshold=1e-4,
    carryover_ratio=0.5,
)
sci_solver = sci_solver_from_integrals(one_body_tensor, two_body_tensor)

def run_sqd(bool_array, label):
    """Run SQD on the samples, and return the final energy and the energy of each round."""
    round_energies = []

    def callback(results):
        round_energies.append(
            min(result.energy for result in results) + core_energy
        )
        print(
            f"{label}, round {len(round_energies)}: {round_energies[-1]:.8f} Ha"
        )

    result = diagonalize_fermionic_hamiltonian(
        one_body_tensor,
        two_body_tensor,
        bool_array,
        samples_per_batch=1000,
        norb=norb,
        nelec=nelec,
        num_batches=NUM_BATCHES,
        max_iterations=MAX_ITERATIONS,
        policy=policy,
        sci_solver=sci_solver,
        symmetrize_spin=True,
        max_dim=int(np.sqrt(SUBSPACE_DIM)),
        initial_occupancies=initial_occupancies,
        callback=callback,
        seed=np.random.default_rng(24),
    )
    return result.energy + core_energy, round_energies

QCSC-Prefect がこのステップを管理する方法

トレース: タスク sqd_loop にはタグ post-process が付いています。サンプルと 積分を受け取るため、グラフでは 2 本の矢印がここに入ります。各バッチは FulqrumSolverJob の 1 回の 呼び出しで、Fulqrum を実行する Slurm ジョブを 1 つ送信する solve_eigenstate タスクです。ラウンド内の バッチは計算ノード上で並行して実行されます。sqd-configuration-recovery アーティファクトには、 すべてのラウンドにおけるすべての部分空間のエネルギーと次元が一覧表示されます。

構成: 実行フォームの SQD グループで、部分空間の次元、バッチ数、ラウンド数を設定します。実行フォームの Solver Block Override (solver_block_ref) は、 1 回の実行について sqd-advanced-settings の Solver Block を置き換えます。たとえば DICE または SBD ブロックに置き換えます。固有値ソルバー (PRIMME)、スレッド、ウォールタイムは sqd-fulqrum-solver ブロックとその実行プロファイルにあります。フローはどのステージよりも前にソルバーブロックを読み込むため、ブロック名が誤っていると、QPU を使う前に実行が失敗します。

再開: sqd_loop はキャッシュされませんが、毎ラウンドの後に、ソルバーの work_dir 以下の sqd_checkpoints/<flow run id>/ckpt_t00_w0.npz にチェックポイントを保存します。チェックポイントには、次のラウンドの初期値となる占有数と、これまでの最良エネルギーが 含まれます。Retry では、sqd_loop は最後に完了したラウンドの後から、現在のブロックで続行します。

オプション: ワークフローの再開と再利用​

失敗した実行を再試行し、そのサンプルを再利用する​

Retry: Max Iteration を 10 に設定した実行で、ラウンド 5 でソルバージョブがウォールタイムに達し、sqd_loop が失敗したとします。Blocks の exec-sqd-fulqrum-slurm ブロックでウォールタイムを延ばし、失敗したフロー実行で Retry を選択します。再試行された実行は、最初の 3 つのステージの保存済みの結果を読み込み、QPU ジョブを送信しません。新しいウォールタイムで sqd_loop だけを再実行し、ラウンド 4 のチェックポイントからラウンド 5 を開始します。ログには [ckpt] RESUME from …: completed 4 step(s) に続いて SQD iteration 5/10 が表示されます。次の画像を参照してください。

再利用: 以前のサンプルを指定しない限り、新しい実行はすべてを再計算します。同じサンプルで別の部分空間の次元を試すには、同じパラメーターでカスタム実行を開始し、Load from QRMI Job Directory (qrmi_result_dir) を最初の実行の sqd-sampling-source アーティファクトにある作業ディレクトリに設定し、Subspace Dimension を変更します。新しい実行は get_lucj_params と quantum_sampling を、サンプルを読み取って QPU には何も送信しない load_qrmi_result に置き換えます。再読み込みでリセット緩和が適用されるため、sqd-advanced-settings の Reset Mitigation は最初の実行と一致している必要があります。IQP 経由で取得したサンプルの場合は、代わりに Load from Qiskit Runtime Job ID (qiskit_runtime_job_id) を設定すると、ステージは load_runtime_job になります。これは、Quantum Runtime Block (reload) (デフォルトは ibm-runner) で指定した prefect-qiskit QuantumRuntime ブロックの認証情報でジョブを読み取ります。このブロックは、prefect block create quantum-runtime で 1 回だけ作成します。

より多くのラウンドで回復を継続する: 同じパラメータでカスタム実行を開始し、Resume from Checkpoint(resume_checkpoint)に最初の実行の sqd-checkpoint アーティファクト内のパスを設定して、Max Iteration を増やします。新しい実行は、保存されている占有数と最良エネルギーから、完了したラウンドの続きを実行します。たとえば、100ラウンド中32ラウンドが完了したチェックポイントで Max Iteration を 200 に設定すると、ラウンド33/200から続行します。新しい実行はそのチェックポイントを読み込み、自身のチェックポイントを書き込みます。また、次のルールが適用されます。

  • サンプル、分子、Subspace Dimension、Batch Number、およびソルバーの種類(ソルバーブロックの fulqrum_solver_job 部分)は最初の実行と一致している必要があります。そのため、Reuse のように最初の実行のサンプルを再利用してください。

  • ソルバーブロックの名前やジョブ設定(ウォールタイムなど)は変更できます。

  • 一致している必要がある設定が異なる場合、実行はソルバージョブの前に失敗し、その違いが示されます。
