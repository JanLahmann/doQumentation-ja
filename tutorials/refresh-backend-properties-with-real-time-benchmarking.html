リアルタイム・ベンチマークを用いたバックエンド・プロパティの更新

使用量の見積もり: 任意の例を含めて ibm_boston で 4 分（注: これはあくまで見積もりです。実際の実行時間は異なる場合があります。）

学習成果​

  • QPU が報告するプロパティがデバイスの現在の挙動と異なる場合がある理由と、自分で再度測定すべき場合

  • 5つの標準的な特性評価実験(読み出し、単一量子ビットランダム化ベンチマーク、階層化された2量子ビットランダム化ベンチマーク、T1T_1T1​、T2T_2T2​)がそれぞれ何を測定するか

  • 1回の呼び出しまたは段階的に、完全な特性評価スイートを実行し、更新されたプロパティを持つバックエンド・オブジェクトを取得する方法

  • 測定されたプロパティを報告されたプロパティと比較する方法、および一部の差異がデバイスのドリフトではなく測定手法を反映している理由

  • 更新したプロパティを量子ビットの選択に使用する方法と、それによって GHZ 状態回路の結果が改善するかどうかを確認する方法

前提条件​

  • Qiskitパターンのワークフロー

  • 実行モード、特に batch mode

  • バックエンド・プロパティやキャリブレーション・データなど、QPU情報を調べる方法

背景​

すべてのIBM Quantum® QPUは、その量子ビットの現在の性能を表す一連のプロパティを報告します。緩和時間(T1T_1T1​)、コヒーレンス時間(T2T_2T2​)、読み出し誤り、1量子ビットおよび2量子ビットのゲート誤りです。これらの数値は実際に重要です。トランスパイラはこれらを使用して回路用の物理量子ビットを選択し、誤り緩和手法はこれらに依存し、また、デバイスが実験に十分機能しているかどうかを判断するためにこれらを利用することもあります。

報告されるプロパティは、通常1日に約1回実行されるキャリブレーション手順から得られます。しかし、超伝導量子ビットはより短い時間スケールでドリフトする可能性があり、一時的な欠陥（2準位系として知られています）が、キャリブレーション時には良好な性能を示していた量子ビットを一時的に劣化させることがあります。さらに、ジョブは実行されるかなり前にトランスパイルされることが多いため、報告されたプロパティに基づく判断が古い情報に依存している可能性があります。

このチュートリアルでは、Qiskit Device Benchmarkingの BackendCharacterization ユーティリティを使用します。このユーティリティは、実験の構築、ジョブの送信、曲線フィッティングを数回の呼び出しにまとめます。約70秒の QPU 時間で、デバイスの現在の状態を反映したプロパティを持つバックエンド・オブジェクトが得られます。これらのプロパティを報告された値と比較したり、バックエンドを他のツールに渡したりできます。最後の例では、更新した値を使用して GHZ 状態回路の物理量子ビットを選択し、その結果を、報告されたプロパティでコンパイルした同じ回路の結果と比較します。

特性評価実験​

このスイートは、それぞれ標準的な実験を用いて5つのプロパティを測定します。

  • 読み出し誤り (readout): この実験では、各量子ビットを ∣0⟩|0\rangle∣0⟩ または ∣1⟩|1\rangle∣1⟩ に準備し、すぐに測定します。誤った読み出しの確率が、状態準備と測定（SPAM）誤りを与えます。

  • 単一量子ビット・ゲート誤り (rb_1q): ランダム化ベンチマーク(RB)は、理想的には恒等演算に合成されるランダムな単一量子ビット・クリフォード・ゲートのシーケンスを実行します。シーケンス長に伴う生存確率の減衰により、SPAM誤りとは独立に、ゲートあたりの平均誤りが得られます。

  • 2量子ビット・ゲート誤り (rb_2q): この実験では、レイヤー忠実度実験のように、同じ RB 手法を、同時に実行される重複のない2量子ビット・ゲートの全レイヤーに適用します。多くのゲートが同時に実行されるため、得られる誤り率にはクロストークの影響が含まれ、深い回路での誤り率に近くなります。

  • T1T_1T1​ (t1): この実験では、各量子ビットを励起し、遅延時間を増やしながら測定します。励起状態の集団の減衰から緩和時間が得られます。

  • T2T_2T2​ (t2): ハーン・エコー実験では、各量子ビットを重ね合わせ状態にし、遅延の途中でエコー・パルスを適用し、量子ビットが位相コヒーレンスをどれだけ速く失うかを測定します。デフォルトでは、この実験は単一のエコーを使用します。このチュートリアルの後半のセクションでは、マルチエコー（CPMG 方式）のバリアントを実演します。

更新されたプロパティの範囲と制限​

このワークフローを使用する際は、以下の点に留意してください。

  • 更新されたプロパティは、ユーティリティがあなたに返すバックエンド・オブジェクト内にのみ存在します。デバイス自体や、IBM Quantumが他のユーザーに報告するキャリブレーション・データには何も変更はありません。

  • 測定された値は、特定の方法論によって取得されたスナップショットです。特に、階層化された2量子ビット誤りと並列化された単一エコーのT2T_2T2​値は、報告されたキャリブレーション・データとは異なる方法で測定されているため、観測される差異の一部はドリフトではなく方法論に由来します。このチュートリアルでは、それが該当する箇所を特定します。

  • 特性評価自体に QPU 時間がかかります（156量子ビットの Heron プロセッサーでの完全なスイートで約70秒）。これは最新の情報を得るためのコストです。

このワークフローは、Qiskitパターンの4つのステップに従います。

  • ステップ1: 古典的な入力を量子問題にマッピングする。 デバイスと測定するプロパティのセットを選択します。

  • ステップ2: 量子ハードウェア実行のために問題を最適化する。 このユーティリティは、実験回路をデバイスのネイティブ・ゲートで直接構築し、デバイス全体に並列化します。

  • ステップ3: Qiskitプリミティブを使用して実行する。 実験はバッチ内のSamplerジョブとして実行されます。

  • ステップ4: 後処理を行い、望ましい古典的な形式で結果を返す。 測定データを量子ビットごとの誤りマップにフィッティングし、バックエンドを更新し、測定されたプロパティを報告されたプロパティと比較します。

必要要件​

このチュートリアルを開始する前に、以下がインストールされていることを確認してください。

  • 可視化サポート付きのQiskit SDK v2.0以降

  • qiskit-ibm-runtime v0.40 or later (pip install qiskit-ibm-runtime)

  • Qiskit Device Benchmarking。これによりQiskit Experimentsもインストールされます(pip install git+https://github.com/qiskit-community/qiskit-device-benchmarking.git)

小規模シミュレーター例​

このチュートリアルにはシミュレーター例は含まれていません。このワークフローは、特定のデバイスの物理的な不完全性、すなわちその量子ビットがどれだけ速く緩和・脱位相するか、そのゲートと読み出しがどれくらいの頻度で失敗するかを測定します。理想的なシミュレーターにはこうした不完全性が一切ないため、特性評価するものがありません。合成ノイズ・モデルをフェイク・バックエンドに付加した場合、実験が復元するのは、モデルに入れた値だけになります。そのため、このチュートリアルでは、Qiskitパターンの4つのステップに沿って、直接ハードウェアに進みます。

大規模ハードウェア例​

ステップ1: 古典的な入力を量子問題にマッピングする​

このワークフローでは、「問題」はデバイス自体です。古典的な入力は、特性評価したいQPUと測定するプロパティのリストです。量子実験は、これらの入力からユーティリティが生成する特性評価回路です。

まず、120量子ビット以上の利用可能な QPU のうち、最も混雑していないものを選択します。このチュートリアルの結果は、2026年10月6日に Heron r3 プロセッサーである ibm_boston で収集されました。

service = QiskitRuntimeService()
backend = service.least_busy(
    operational=True,
    simulator=False,
    min_num_qubits=120,
)

次に、測定するプロパティを選択します。以下の実験の任意の部分集合を渡すことができます。

  • readout: SPAM(状態準備と測定)実験

  • rb_1q: 独立した単一量子ビット・ランダム化ベンチマーク

  • rb_2q: レイヤー忠実度実験による同時2量子ビット・ランダム化ベンチマーク

  • t2: T2T_2T2​ ハーン・エコー実験(デフォルトでは単一エコー)

  • t1: T1T_1T1​緩和実験

完全なスイートを実行して、デバイスを完全に特性評価します。QPU 時間を節約するには、不要なプロパティのエントリを削除してください。

experiments = ["readout", "rb_1q", "rb_2q", "t1", "t2"]

ステップ2: 量子ハードウェア実行のために問題を最適化する​

ほとんどのチュートリアルでは、このステップで回路をトランスパイルします。このチュートリアルでは、BackendCharacterization が内部でトランスパイルを処理します。デバイスのネイティブ・ゲートで実験回路を直接構築し、すべての量子ビットで単一量子ビット実験を並列に実行し、結合マップの互いに素なレイヤーにわたって2量子ビットのベンチマークをスケジュールすることで、少数のジョブでデバイス全体をカバーします。この並列化のおかげで、一連の実験全体で使用する QPU 時間は約70秒だけです。

ワークフローを管理するクラスを初期化します。

# Initialize the class used to run the experiments
characterizer = BackendCharacterization(backend)

ステップ3: Qiskitプリミティブを使用して実行する​

run_experimentsメソッドは回路を構築し、それらをSamplerジョブとして送信します。ジョブがQPU上でまとめてスケジュールされるように、これをBatchコンテキスト内で実行してください。このメソッドは、すべてのジョブを送信した後に戻ります。Batchの外部や、Session内で実行することもできます。

備考

セッション・コンテキスト・マネージャーが開いている状態でバックエンドが渡された、という警告が表示される場合があります。この警告は想定されたものであり、無視しても問題ありません。レイヤー忠実度実験では、オプションの xslow ゲートを使用しないという警告も表示される場合があります。この実験はサポートされている標準の単一量子ビット・ゲートを使用するため、この警告も無視できます。

# Run the characterization experiments inside a Batch
with Batch(backend=backend):
    jobs = characterizer.run_experiments(experiments=experiments)

ステップ4: 後処理を行い、目的の古典形式で結果を返す​

結果を分析する​

analyze_results メソッドはジョブの終了を待ち、その後、測定データを処理します。T1T_1T1​ と T2T_2T2​ のデータには指数関数的減衰を、RB データには生存確率の減衰をフィッティングし、読み出しについては割り当て行列を計算します。戻り値は誤りマップのディクショナリで、測定したプロパティごとに1エントリを持ちます。各誤りマップは、各量子ビット（または量子ビットのペア）に測定値を割り当てます。

error_maps = characterizer.analyze_results()
print(f"The following error maps are available: {list(error_maps.keys())}")
readout_q0 = error_maps["readout_error"][0]
print(f"For example, readout error for qubit 0 is {readout_q0}")

このマップは、読み出しエラー、単一量子ビットのxゲートとsxゲートのエラー、レイヤー化された2量子ビットのエラー(レイヤー忠実度実験によるlf_error_map)、そして秒単位のT1T_1T1​とT2T_2T2​の時間をカバーしています。

バックエンド・プロパティを更新する​

update_backend メソッドは、測定値をバックエンドのコピーのプロパティに書き込み、そのコピーを返します。元の backend オブジェクトは報告されたキャリブレーション・データを保持したままなので、次のセクションで示すように、2つのプロパティのセットを比較できます。この更新は、お使いの Python セッションにのみ適用されます。デバイス上や他のユーザーに対しては何も変更しません。

backend_updated = characterizer.update_backend()

測定されたプロパティと報告されたプロパティを比較する​

最後に、測定されたリアルタイムのプロパティを、バックエンドが報告する値に対してプロットします。各パネルでは、量子ビット（または量子ビットのペア）は測定値でソートされているため、測定曲線は構成上滑らかになります。この曲線の周りに散らばる報告値のばらつきは、2つのデータセットが一致しない箇所を示します。単一量子ビット RB の結果は1つのプロットに表示されます。これは、このユーティリティがゲートあたりの同じ測定誤りを x ゲートと sx ゲートの両方に割り当てるためです。軸の範囲はデータの大部分に基づいているため、いくつかの極端な外れ値によってプロットが圧縮されることはありません。各プロットの注釈には、範囲外の点の数が示されます。範囲を自分で設定するには、ylim 引数を渡します。

plot_characterization_comparison(
    old_props=backend.properties().to_dict(),
    new_props=backend_updated.properties().to_dict(),
    plots=["readout", "rb_1q", "rb_2q", "t1", "t2"],
)

これらのプロットは注意深く読んでください。2つの曲線間のすべてのギャップが、デバイスがドリフトしたことを意味するわけではないからです。

  • 読み出しと単一量子ビットのエラー: 測定値はほとんどの量子ビットで報告値に沿っていますが、数個の量子ビットでは報告値が測定曲線から大きく外れています。これらの局所的な不一致は、このワークフローが検出するよう設計されているドリフトを反映している可能性があります。

  • T1T_1T1​: 2つのデータセットは体系的なオフセットなしにお互いの周りに散らばっており、これは時間の経過に伴うT1T_1T1​の自然な変動と一致しています。

  • 2量子ビットのエラー: 測定値は報告値よりも体系的に高くなっています。これは予想されることです。報告値は孤立したゲートから得られたものであるのに対し、レイヤー忠実度実験は多数のゲートを同時に実行するため、クロストークが含まれるからです。レイヤー化された値は深い回路にとってより関連性が高いですが、報告されたキャリブレーション・データと直接比較することはできません。

  • T2T_2T2​: 測定値はほとんどの量子ビットで報告値よりもかなり低くなっています。2量子ビットのエラーと同様に、手法が大きな役割を果たしており、これについては次のセクションで検討します。

個々の実験結果を検査する​

また、experiment_dataプロパティを通じて、個々の特性評価実験の生の結果を検査することもできます。これは、基盤となるQiskit ExperimentsのExperimentDataオブジェクトを返します。例えば、次のコードは単一量子ビットの測定されたT1T_1T1​減衰曲線を表示します。フィットが算出した値を信頼する前に、この例のような曲線を使ってフィットの品質を確認してください。

ダイナミカル・デカップリング・トレインでT2を測定する​

デフォルトでは、T2T_2T2​ 実験は単一のハーン・エコーを適用し、すべての量子ビットを並列に測定します。前の比較プロットが示すように、この手法では、バックエンドが報告するよりも著しく低い T2T_2T2​ 値が得られることがあります。考えられる原因の1つはエコーの数です。報告された値は、低周波ノイズを抑制するダイナミカル・デカップリングを用いたキャリブレーションによるものかもしれません。この仮説を検証するために、CPMG 方式のエコー・パルス列を適用する、より大きな t2_num_echoes の値で T2T_2T2​ のみの特性評価を実行します。どちらの場合も、遅延は自由時間発展の合計時間を表すため、フィットされた T2T_2T2​ 値は単一エコーの結果と直接比較できます。

ステップ1~4を1回の呼び出しで実行する​

通常の使用では、中間結果が必要になることはほとんどありません。run_and_updateメソッドは、これまでのステップ(構築、送信、フィッティング、更新)を1回の呼び出しにまとめ、更新されたバックエンドを返します。同じexperimentsリストを受け付け、t2_num_echoesなどのオプションも転送します。BatchやSessionのコンテキストでラップすることもできます。

更新されたプロパティを量子ビット選択に使用する​

このオプションの例でワークフローは完結します。更新されたプロパティによって、回路の結果が改善されるかどうかを確認します。同じ回路を2回コンパイルします。1回は報告されたプロパティで、もう1回は更新されたプロパティでコンパイルします。その後、両方のバージョンを実行して出力を比較します。この例では、前のセクションのbackendおよびbackend_updatedオブジェクトを使用し、QPUに追加のジョブを送信します。

比較用の回路を構築する​

アダマール・ゲートとそれに続くCNOTゲートの連鎖でnnn量子ビットのグリーンバーガー・ホーン・ツァイリンガー(GHZ)状態を準備し、すべての量子ビットを測定します。理想的には、結果∣0⋯0⟩|0\cdots0\rangle∣0⋯0⟩と∣1⋯1⟩|1\cdots1\rangle∣1⋯1⟩の確率はそれぞれ0.5です。すべての量子ビットを測定するため、連鎖内のいずれかの量子ビットで発生したエラー(読み出しエラーを含む)は、理想的な結果の確率を低下させます。したがって、測定された出力は、トランスパイラーが選択する物理量子ビットに敏感です。

更新されたプロパティは、トランスパイラーが多くの候補となる量子ビットの連鎖から選択できる中程度のサイズで最も重要になる傾向があります。非常に大きな回路はデバイスの大部分を使用するため、トランスパイラーが性能の低い量子ビットを避ける余地はほとんどありません。QPU時間を節約するには、回路サイズのリストを減らしてください。

num_qubits_list = list(range(5, 41, 5))
circuits = []
for num_qubits in num_qubits_list:
    circuit = QuantumCircuit(num_qubits)
    circuit.h(0)
    for qubit in range(num_qubits - 1):
        circuit.cx(qubit, qubit + 1)
    circuit.measure_all()
    circuits.append(circuit)

circuits[1].draw(output="mpl", style="clifford", fold=-1)

報告されたプロパティと更新されたプロパティでトランスパイルする​

トランスパイラーはTargetを使用して、物理量子ビットとネイティブ命令を選択します。バックエンドのプロパティのみを更新しても、既存のターゲットは変更されないままになる場合があります。代わりに、元のターゲットをコピーし、更新されたエラーとコヒーレンス時間をそのコピーに明示的に適用します。コピーは、元の命令の継続時間と接続性を保持します。ある量子ビットのコヒーレンス時間が利用できない場合は、ターゲットの既存の値を保持します。

報告されたエラーが1の場合、その量子ビットまたはゲートのベンチマーキングが数日間成功しておらず、値が古いため、エラーが未定義であることを意味します(QPU情報を参照)。この値は必ずしもゲートが動作していないことを意味するわけではありませんが、そのゲートは慎重に扱う必要があります。1回のキャラクタリゼーション実行で、そのようなゲートに低いエラーがフィットされることがあり、そのゲートがデバイス上で最も優れたものの1つに見えてしまう場合があります。慎重を期すため、これらのエントリは報告された値のままにして、トランスパイラーがそれらを避け続けるようにします。

トランスパイラーのランダム性を制御して比較できるよう、両方のコンパイルで同じ最適化レベルとランダム・シードを使用します。

target_updated = deepcopy(backend.target)
properties_updated = backend_updated.properties()

for gate in properties_updated.gates:
    if not any(
        parameter.name == "gate_error" for parameter in gate.parameters
    ):
        continue
    qargs = tuple(gate.qubits)
    if gate.gate not in target_updated.operation_names:
        continue
    if qargs not in target_updated[gate.gate]:
        continue
    instruction_properties = deepcopy(target_updated[gate.gate][qargs])
    # Keep gates whose reported error is undefined (error of 1)
    if (
        instruction_properties is not None
        and instruction_properties.error < 1
    ):
        instruction_properties.error = properties_updated.gate_error(
            gate.gate, qargs
        )
        target_updated.update_instruction_properties(
            gate.gate, qargs, instruction_properties
        )

for qubit in range(backend.num_qubits):
    measurement_properties = deepcopy(target_updated["measure"][(qubit,)])
    if measurement_properties.error < 1:
        measurement_properties.error = properties_updated.readout_error(qubit)
        target_updated.update_instruction_properties(
            "measure", (qubit,), measurement_properties
        )
    qubit_properties = properties_updated.qubit_property(qubit)
    if "T1" in qubit_properties:
        target_updated.qubit_properties[qubit].t1 = qubit_properties["T1"][0]
    if "T2" in qubit_properties:
        target_updated.qubit_properties[qubit].t2 = qubit_properties["T2"][0]

pm_reported = generate_preset_pass_manager(
    target=backend.target, optimization_level=3, seed_transpiler=42
)
pm_refreshed = generate_preset_pass_manager(
    target=target_updated, optimization_level=3, seed_transpiler=42
)
isa_reported = pm_reported.run(circuits)
isa_refreshed = pm_refreshed.run(circuits)

両方の回路セットを実行する​

同じQPU上で、同じショット数とエラー抑制設定を使用して両方のバージョンを実行します。報告されたバージョンと更新されたバージョンを交互に配置して送信し、比較を3回繰り返して試行間のばらつきを観察します。送信の順序は実行の順序を保証せず、交互配置によってドリフトが解消されるわけではありません。

n_trials = 3
shots = 4096
interleaved_circuits = [
    circuit for pair in zip(isa_reported, isa_refreshed) for circuit in pair
]
sampler = SamplerV2(mode=backend)
sampler.options.environment.job_tags = ["TUT_RTBQS"]
sampler.options.dynamical_decoupling.enable = True
sampler.options.dynamical_decoupling.sequence_type = "XY4"
comparison_job = sampler.run(interleaved_circuits * n_trials, shots=shots)
print(f"Comparison job ID: {comparison_job.job_id()}")

出力分布を比較する​

測定された各分布と理想的なGHZ分布との間のヘリンジャー忠実度を計算します。値が1の場合、分布が一致していることを意味します。この指標は計算基底での一致のみを測定します。∣0⋯0⟩|0\cdots0\rangle∣0⋯0⟩と∣1⋯1⟩|1\cdots1\rangle∣1⋯1⟩の間のコヒーレンスは測定しないため、GHZ状態の忠実度の上限であり、エンタングルメントの証明ではありません。

プロットは試行全体の平均を示しています。エラーバーは1標準偏差を示します。

comparison_results = comparison_job.result()
fidelities = np.empty((n_trials, len(num_qubits_list), 2))
for trial in range(n_trials):
    for chain_index in range(len(num_qubits_list)):
        for variant in range(2):
            result_index = (
                trial * 2 * len(num_qubits_list) + 2 * chain_index + variant
            )
            counts = comparison_results[result_index].data.meas.get_counts()
            num_qubits = num_qubits_list[chain_index]
            ideal_dist = {"0" * num_qubits: 0.5, "1" * num_qubits: 0.5}
            fidelities[trial, chain_index, variant] = hellinger_fidelity(
                ideal_dist, counts
            )

更新されたプロパティが、より良い結果を保証するわけではありません。その効果は、前回のキャリブレーション以降にデバイスがどれだけドリフトしたかによって決まります。また、キャラクタリゼーション自体もノイズを含むスナップショットです。トランスパイラーは、たまたま良好に測定された量子ビットやゲートを、実際には性能が優れていなくても選択する可能性があります。ショット・ノイズ、キャラクタリゼーションから実行までの間のさらなるドリフト、およびキャラクタリゼーション手法の違いも、比較に影響します。測定された変化とそのばらつきを使用して、更新されたプロパティがワークロードに有用かどうかを判断してください。
