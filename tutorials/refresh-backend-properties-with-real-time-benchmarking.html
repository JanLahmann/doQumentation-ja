リアルタイム・ベンチマークを用いたバックエンド・プロパティの更新

使用量の見積もり: ibm_kingstonで3分(注:これはあくまで見積もりです。実際の実行時間は異なる場合があります。)

学習成果​

このチュートリアルを完了することで、以下について理解できるようになります。

  • QPUが報告するプロパティがデバイスの現在の挙動から遅れる可能性がある理由と、自分で再測定する価値がある場合

  • 5つの標準的な特性評価実験(読み出し、単一量子ビットランダム化ベンチマーク、階層化された2量子ビットランダム化ベンチマーク、T1T_1T1​、T2T_2T2​)がそれぞれ何を測定するか

  • 1回の呼び出しまたは段階的に、完全な特性評価スイートを実行し、更新されたプロパティを持つバックエンド・オブジェクトを取得する方法

  • 測定されたプロパティを報告されたプロパティと比較する方法、および一部の差異がデバイスのドリフトではなく測定手法を反映している理由

前提条件​

以下のトピックに慣れておくことをお勧めします。

  • Qiskitパターンのワークフロー

  • Qiskit Runtime実行モード、特にバッチ・モード

  • バックエンド・プロパティやキャリブレーション・データなど、QPU情報を調べる方法

背景​

すべてのIBM Quantum® QPUは、各量子ビットが現在どの程度うまく機能しているかを表す一連のプロパティを報告します。緩和時間(T1T_1T1​)、コヒーレンス時間(T2T_2T2​)、読み出し誤り、1量子ビットおよび2量子ビットのゲート誤りです。これらの数値は実際に重要です。トランスパイラはこれらを使用して、回路をどの物理量子ビット上で実行すべきかを決定し、誤り抑制技術はこれらに依存し、また、デバイスが実験に十分機能しているかどうかを判断するためにこれらを利用することもあります。

報告されるプロパティは、通常1日に約1回実行されるキャリブレーション手順から得られます。しかし、超伝導量子ビットはより短い時間スケールでドリフトする可能性があり、一時的な欠陥(いわゆる2準位系)が、キャリブレーション時には優れていた量子ビットを一時的に劣化させることがあります。さらに、ジョブは実際に実行されるかなり前にトランスパイルされることが多いため、報告されたプロパティに基づく判断が古い情報に依存している可能性があります。チュートリアル量子ビット選択のためのリアルタイム・ベンチマークでは、これらのプロパティが日々どれほど変動しうるかを示し、個々のQiskit Experimentsから手作業で完全な特性評価ワークフローを構築しています。

このチュートリアルでは、Qiskit Device BenchmarkingのBackendCharacterizationユーティリティを使用することで、そのワークフローの効率化されたバージョンを示します。このユーティリティは、実験の構築、ジョブの送信、曲線フィッティングを数回の呼び出しにパッケージ化します。約70秒のQPU時間を費やすことで、現在のデバイスの状態を反映したプロパティを持つバックエンド・オブジェクトが得られ、報告された値と比較したり、下流のツールに渡したりする準備が整います。

特性評価実験​

このスイートは、それぞれ標準的な実験を用いて5つのプロパティを測定します。

  • 読み出し誤り (readout): 各量子ビットは∣0⟩|0\rangle∣0⟩または∣1⟩|1\rangle∣1⟩に準備され、すぐに測定されます。誤った状態を読み出す確率が、状態準備と測定(SPAM)誤りを与えます。

  • 単一量子ビット・ゲート誤り (rb_1q): ランダム化ベンチマーク(RB)は、理想的には恒等演算に合成されるランダムな単一量子ビット・クリフォード・ゲートのシーケンスを実行します。生存確率がシーケンス長とともにどのように減衰するかによって、SPAM誤りとは独立に、ゲートあたりの平均誤りが得られます。

  • 2量子ビット・ゲート誤り (rb_2q): 同じRBの考え方を、レイヤー忠実度実験のように、同時に実行される重複のない2量子ビット・ゲートの全レイヤーに適用します。多くのゲートが同時に実行されるため、得られる誤り率にはクロストークの影響が含まれ、深い回路が実際に経験するものに近くなります。

  • T1T_1T1​ (t1): 各量子ビットが励起され、遅延時間を増やしながら測定されます。励起状態の集団の減衰から緩和時間が得られます。

  • T2T_2T2​ (t2): ハーン・エコー実験では、各量子ビットを重ね合わせ状態にし、遅延の途中でエコー・パルスを適用し、位相コヒーレンスがどれだけ速く失われるかを測定します。デフォルトでは単一のエコーが使用されますが、マルチエコー(CPMG方式)のバリアントがこのチュートリアルの最後で実演されます。

更新が行うこと・行わないこと​

このワークフローを使用する際は、以下の3点に留意してください。

  • 更新されたプロパティは、あなたに返されるバックエンド・オブジェクト内にのみ存在します。デバイス自体や、IBM Quantumが他のユーザーに報告するキャリブレーション・データには何も変更はありません。

  • 測定された値は、特定の方法論によって取得されたスナップショットです。特に、階層化された2量子ビット誤りと並列化された単一エコーのT2T_2T2​値は、報告されたキャリブレーション・データとは異なる方法で測定されているため、観測される差異の一部はドリフトではなく方法論によるものです。このチュートリアルでは、それが該当する箇所を指摘します。

  • 特性評価自体にはQPU時間がかかります(Heron r2プロセッサーでの完全なスイートで約70秒)。これは最新の情報を得るための代償です。

このワークフローは、Qiskitパターンの4つのステップに従います。

  • ステップ1: 古典的な入力を量子問題にマッピングする。 デバイスと測定するプロパティのセットを選択します。

  • ステップ2: 量子ハードウェア実行のために問題を最適化する。 このユーティリティは、実験回路をデバイスのネイティブ・ゲートで直接構築し、チップ全体に並列化します。

  • ステップ3: Qiskitプリミティブを使用して実行する。 実験はバッチ内のSamplerジョブとして実行されます。

  • ステップ4: 後処理を行い、望ましい古典的な形式で結果を返す。 測定データを量子ビットごとの誤りマップにフィッティングし、バックエンドを更新し、測定されたプロパティを報告されたプロパティと比較します。

必要要件​

このチュートリアルを開始する前に、以下がインストールされていることを確認してください。

  • 可視化サポート付きのQiskit SDK v2.0以降

  • Qiskit Runtime v0.40以降(pip install qiskit-ibm-runtime)

  • Qiskit Device Benchmarking。これによりQiskit Experimentsもインストールされます(pip install git+https://github.com/qiskit-community/qiskit-device-benchmarking.git)

小規模シミュレーター例​

このチュートリアルにはシミュレーター例は含まれていません。このワークフローは、特定のデバイスの物理的な不完全性、すなわちその量子ビットがどれだけ速く緩和・脱位相するか、そのゲートと読み出しがどれくらいの頻度で失敗するかを測定します。理想的なシミュレーターにはこうした不完全性が一切ないため、特性評価するものがありません。フェイク・バックエンドに合成ノイズ・モデルを付加することもできますが、その場合、実験は自分で入力した数値を回復するだけになってしまいます。そのため、ここではQiskitパターンの4つのステップに分けて、直接ハードウェアに進みます。

大規模ハードウェア例​

ステップ1: 古典的な入力を量子問題にマッピングする​

このワークフローでは、「問題」はデバイス自体です。古典的な入力は、特性評価したいQPUと測定するプロパティのリストであり、量子実験はそれらから生成された特性評価回路です。

まず、バックエンドを選択します。このチュートリアルでは、156量子ビットのHeron r2プロセッサーであるibm_kingstonを使用します。アクセス可能な任意のIBM Quantumデバイスに置き換えることができます(またはservice.least_busy()で1つを選ぶこともできます)。

service = QiskitRuntimeService()
device = "ibm_kingston"
backend = service.backend(device)

次に、測定するプロパティを選択します。以下の実験の任意の部分集合を渡すことができます。

  • readout: SPAM(状態準備と測定)実験

  • rb_1q: 独立した単一量子ビット・ランダム化ベンチマーク

  • rb_2q: レイヤー忠実度実験による同時2量子ビット・ランダム化ベンチマーク

  • t2: T2T_2T2​ Hahn echo実験(デフォルトではシングルエコー)

  • t1: T1T_1T1​緩和実験

完全な一連の実験を実行してデバイスの全体像を把握してください。特定のプロパティのみに関心があり、QPU時間を節約したい場合は、リストからエントリを削除してください。

experiments = ["readout", "rb_1q", "rb_2q", "t1", "t2"]

ステップ2: 量子ハードウェア実行のために問題を最適化する​

ほとんどのチュートリアルでは、ここで回路をトランスパイルします。ここでは、BackendCharacterizationが内部でそれを処理します。デバイスのネイティブ・ゲートで実験回路を直接構築し、すべての量子ビットで単一量子ビット実験を並列に実行し、結合マップの互いに素なレイヤーにわたって2量子ビットのベンチマークをスケジュールすることで、少数のジョブでデバイス全体をカバーします。この並列化のおかげで、一連の実験全体で消費されるQPU時間は約70秒だけです。

ワークフローを管理するクラスを初期化します。

# Initialize the class used to run the experiments
characterizer = BackendCharacterization(backend)

ステップ3: Qiskitプリミティブを使用して実行する​

run_experimentsメソッドは回路を構築し、それらをSamplerジョブとして送信します。ジョブがQPU上でまとめてスケジュールされるように、これをBatchコンテキスト内で実行してください。このメソッドは、すべてのジョブが送信されると値を返します。(バッチの外部や、Session内で実行することもできます。)

ステップ4: 後処理を行い、目的の古典形式で結果を返す​

結果を分析する​

analyze_resultsメソッドはジョブの終了を待ち、測定データをフィッティングします。T1T_1T1​とT2T_2T2​については指数関数的減衰、RB実験については生存確率の減衰、読み出しについては割り当て行列です。これは誤差マップのディクショナリを返します。これは測定されたプロパティごとに1つのエントリがあり、それぞれが量子ビット(または量子ビットのペア)をその測定値にマッピングします。

error_maps = characterizer.analyze_results()
print(f"The following error maps are available: {list(error_maps.keys())}")
readout_q0 = error_maps["readout_error"][0]
print(f"For example, readout error for qubit 0 is {readout_q0}")
The following error maps are available: ['readout_error', 'oneq_error_x', 'oneq_error_sx', 'lf_error_map', 't1_map', 't2_map']
For example, readout error for qubit 0 is 0.007600000000000051

このマップは、読み出しエラー、単一量子ビットのxゲートとsxゲートのエラー、レイヤー化された2量子ビットのエラー(レイヤー忠実度実験によるlf_error_map)、そして秒単位のT1T_1T1​とT2T_2T2​の時間をカバーしています。

バックエンド・プロパティを更新する​

update_backendメソッドは、測定値をバックエンドのコピーのプロパティに書き込み、それを返します。元のbackendオブジェクトは報告されたキャリブレーション・データを保持したままなので、以下に示すように両者を比較できます。この更新は、あくまでPythonセッションにローカルなものであり、デバイス上や他のユーザーに対して何も変更しないことに注意してください。

backend_updated = characterizer.update_backend()

測定されたプロパティと報告されたプロパティを比較する​

最後に、測定されたリアルタイムのプロパティを、バックエンドが報告する値に対してプロットします。各パネルでは、量子ビット(または量子ビットのペア)は測定値でソートされているため、測定曲線は構造的に滑らかになり、その周りに散らばる報告値のばらつきによって両者の不一致がどこにあるかがわかります。単一量子ビットRBでは、同じ測定誤差がxゲートとsxゲートの両方に割り当てられるため、単一のプロットが表示されます。軸の範囲はデータの大部分から選択されるため、いくつかの極端な外れ値によってプロットが圧縮されることはありません。範囲外の点は、プロット上の注釈でカウントされます(または、ylimを渡して範囲を上書きできます)。

plot_characterization_comparison(
    old_props=backend.properties().to_dict(),
    new_props=backend_updated.properties().to_dict(),
    plots=["readout", "rb_1q", "rb_2q", "t1", "t2"],
)

これらのプロットは注意深く読む必要があります。両曲線間のすべてのギャップがデバイスのドリフトを意味するわけではないからです。

  • 読み出しと単一量子ビットのエラー: 測定値はほとんどの量子ビットで報告値に沿っていますが、一握りの量子ビットの報告値は測定曲線から大きく外れています。これらの局所的な不一致こそ、このワークフローが検出するように設計されているドリフトです。

  • T1T_1T1​: 2つのデータセットは体系的なオフセットなしにお互いの周りに散らばっており、これはT1T_1T1​が時間の経過とともに自然に変動することと一致しています。

  • 2量子ビットのエラー: 測定値は報告値よりも体系的に高くなっています。これは予想通りです。報告値は孤立したゲートで測定されているのに対し、レイヤー忠実度実験は多数のゲートを同時に実行するため、クロストークが含まれるからです。レイヤー化された数値は深い回路にとってより関連性が高いですが、報告されたキャリブレーション・データと直接比較することはできません。

  • T2T_2T2​: 測定値はほとんどの量子ビットで報告値よりもかなり低くなっています。ここでも、次のセクションで検討するように、手法が大きな役割を果たします。

個々の実験結果を検査する​

また、experiment_dataプロパティを通じて、個々のキャラクタリゼーション実験の生の結果を検査することもできます。これは、基盤となるQiskit ExperimentsのExperimentDataオブジェクトを返します。例えば、以下では単一量子ビットの測定されたT1T_1T1​減衰曲線を表示しています。これは、フィットが算出した数値を信頼する前に、フィットの品質を確認するのに役立ちます。

t1_data = characterizer.experiment_data["t1"]

# Each qubit has its own fit figure
n_figs = len(t1_data.figure_names)
print(f"{n_figs} figures available, e.g. {t1_data.figure_names[0]}")

# Show the T1 decay curve of the first qubit
t1_data.figure(0)

ダイナミカル・デカップリング・トレインでT2を測定する​

デフォルトでは、T2T_2T2​実験は単一のHahnエコーを適用し、すべての量子ビットを並列に測定します。これは、上記の比較プロットが示したように、バックエンドが報告するよりも著しく低いT2T_2T2​値をもたらす可能性があります。1つの仮説はエコーの数です。報告された値は、低周波ノイズを抑制するダイナミカル・デカップリングを用いてキャリブレーションされている可能性があります。これを検証するために、t2_num_echoesをより大きな値に設定してT2T_2T2​のみのキャラクタリゼーションを実行します。これにより、CPMGスタイルのエコー・パルス列が適用されます。両方のケースで、遅延は自由時間発展の合計時間を表すため、フィットされたT2T_2T2​値はシングルエコーの結果と直接比較可能です。

# Run a T2-only characterization using a CPMG-style train of 8 echoes
characterizer_dd = BackendCharacterization(backend)
backend_updated_dd = characterizer_dd.run_and_update(
    experiments=["t2"], t2_num_echoes=8
)

Median T2 — reported: 142 us | single echo: 53 us | 8-echo CPMG: 56 us

この実行では、追加のエコーによって結果はほとんど変化しませんでした。8エコーの中央値(56 µs)はシングルエコーの中央値(53 µs)に近く、両方とも報告された中央値(142 µs)を大きく下回ったままです。エコーの数だけではこのギャップを説明できません。キャリブレーション手順の詳細や、量子ビットを孤立させずにすべて並列に測定していることなど、他の方法論上の違いが関係しています。

実用上の教訓は、手法をまたいだT2T_2T2​(およびレイヤー化された2量子ビットのエラー)の比較には注意が必要だということです。更新された値は、実際のワークロードに近い条件下で取得された自己無矛盾なスナップショットであり、量子ビット同士を比較したり、デバイスを長期にわたって追跡したりするのに適しています。しかし、報告されたキャリブレーション・データとのギャップは、自動的にドリフトの証拠になるわけではありません。

ステップ1~4を1回の呼び出しに圧縮する​

日常の使用では、中間結果が必要になることはほとんどありません。run_and_updateメソッドは、上記で行ったすべての処理(構築、送信、フィッティング、更新)を1回の呼び出しに連結し、更新されたバックエンドを返します。これは同じexperimentsリストを受け付け(t2_num_echoesなどのオプションも転送します)、BatchやSessionのコンテキストでラップすることも同様に可能です。
