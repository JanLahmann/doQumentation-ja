SQOA Solver - JIJ 社による Qiskit Function

API リファレンスをご覧ください。

備考

Qiskit Functions は実験的な機能であり、IBM Quantum® Premium Plan、Flex Plan、On-Prem (IBM Quantum Platform API 経由) Plan のユーザーのみが利用できます。プレビューリリースの状態であり、変更される場合があります。

概要​

JIJ 社の SQOA Solver を使うと、IBM® の量子コンピューターで大規模な組合せ最適化問題を解くことができます。このソルバーは、Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) [1] に基づいています。古典的な決定変数と量子ビットを一対一で対応させる量子アルゴリズムとは異なり、SQOA Solver は、現在の量子デバイスで利用可能な量子ビット数よりも多くの変数を持つ最適化問題を扱えます。また、サンプリングに基づく設計のため、現在の量子ハードウェアの物理ノイズの影響を受けにくくなっています。これらの特長により、SQOA Solver は、量子コンピューティングの現段階における最適化問題に適しています。

このソルバーは、古典的な数式として与えられた二次制約なし二値最適化 (QUBO) 問題を扱い、古典的な定式化を量子の設定に自動的に変換します。ペナルティ法を使えば、制約付きの問題を制約なしの問題に変換することもできます。

以降のセクションでは、ソルバーのワークフロー、ベンチマーク結果、そして qiskit-addon-opt-mapper と、必要に応じて Open Mathematical prograMming eXchange (OMMX) で問題をモデル化するエンドツーエンドの例を説明します。OMMX は、ソフトウェアツール間での最適化問題のやり取りを簡単にする、オープンなデータ形式および SDK です。

説明​

SQOA Solver は Sampling-based Quantum Optimization Algorithm with Quantum Relaxation (SQOA-QR) を実装し、その前後に古典的な前処理と後処理を組み合わせています。このセクションでは、SQOA フレームワークと、それが Quantum Approximate Optimization Algorithm (QAOA) とどう違うのかを説明します。

次の図は、SQOA Solver のワークフローの概略を示しています。

SQOA フレームワーク​

SQOA は、組合せ最適化のためのサンプリングベースのフレームワークです [1]。これは 2 つの技術を組み合わせています。1 つは、問題を量子緩和として符号化する Quantum Random Access Optimization (QRAO) [2] です。もう 1 つは、sample-based quantum diagonalization (SQD) [3] で、quantum-selected configuration interaction (QSCI) [4] としても知られ、量子コンピューターをビット列のサンプリングにのみ使い、低エネルギー状態を古典コンピューターで求めます。SQOA は、この組合せを固定しつつ、変数を量子ビットに割り当てる方法やサンプルを生成する回路など、詳細は各実装に委ねるという意味でのフレームワークです。

  • QRAO による量子緩和。 QAOA などの Ising ベースの手法では、各二値変数をその量子ビットの ZZZ 演算子で表現します。QRAO では XXX 演算子と YYY 演算子も使います。(3,1) 量子ランダムアクセスコード (QRAC) では、最大 3 つの二値変数が 1 つの量子ビットを共有し、各変数は異なるパウリ演算子で表現されます。

    これにより QUBO は、Ising ハミルトニアンよりも少ない量子ビットで済む緩和ハミルトニアンになります。QUBO で相互作用する変数は、異なる量子ビットに配置しなければなりません。同じ量子ビットを共有すると、それらのパウリ演算子の積がその量子ビット上の単一の演算子に簡約され (たとえば XY=iZXY = iZXY=iZ)、緩和ハミルトニアンがそれらの相互作用を表現できなくなってしまいます。

    したがって、変数の量子ビットへの割り当てが、量子ビット数と緩和の質の両方を決めるため、SQOA Solver は前処理でこの割り当てを設計します。

  • Sample-based quantum diagonalization (SQD)。 量子コンピューターはまず、緩和ハミルトニアンの低エネルギー状態と重なりを持つ量子状態を準備し、そこからビット列をサンプリングします。古典コンピューターは、緩和ハミルトニアンをサンプリングされたビット列が張る部分空間に射影し、対角化して基底状態を近似します。

    緩和ハミルトニアンは非対角であるため、対角化ではサンプリングされたビット列が重ね合わせに組み合わされます。対角な Ising ハミルトニアンの場合、すべてのビット列がすでに固有状態であり、対角化は最良のサンプルを選ぶだけになってしまいます。同じアプローチは、量子化学における大規模な問題にも適用されています。

SQD で得られる近似基底状態は、元の問題の古典的な解に直接対応しないため、そこから古典的な解を復号する必要があります。この状態は古典コンピューターで計算されるため、丸め (rounding) と呼ばれる復号は古典的な後処理です。SQOA Solver は、ヒューリスティックにより良い古典解を得るよう設計された復号技術を使用します。

次の表は、SQOA を、同じクラスの問題に対する一般的な変分アプローチである QAOA と比較したものです。

qiskit-addon-opt-mapper で入力を準備する​

このガイドでは、qiskit-addon-opt-mapper の OptimizationProblem クラスで問題をモデル化します。SQOA Solver は、IBM の最適化関数で使われるタプル文字列形式の係数辞書として QUBO 問題を受け付けるため、このガイドのすべての例は、同じクライアント側の準備パターンに従います。

  1. モデルを記述する。 OptimizationProblem を作成し、二値決定変数を追加して、目的関数と必要な制約を設定します。

  2. QUBO に変換する。 OptimizationProblemToQubo で問題を変換します。これは、制約をペナルティ項として目的関数に加え、等価な制約なしの最小化問題を返します。

  3. 辞書に変換する。 QUBO を、次のセクションで定義する to_problem_dict() ヘルパー関数に渡し、その結果を variable_type="binary" とともに problem として solver.run() に渡します。

SQOA Solver は辞書形式の問題を常に最小化します。これは OptimizationProblemToQubo が返す最小化問題と一致します。そのため、最大化問題では、返される objective_value は元の目的関数の符号を反転した値になります。元の問題の観点で結果を読み取るには、例で示すように、返された割り当てを OptimizationProblem で評価します。辞書形式の詳細は、API リファレンスの対応している問題形式を参照してください。

# %pip install qiskit-addon-opt-mapper

次のヘルパー関数を一度定義し、すべての例で再利用します。これは、OptimizationProblemToQubo が返す QUBO を辞書形式に変換します。キーには QUBO の変数インデックスが使われるため、結果の解のキー x_0、x_1 などは、そのインデックスに対応します。返される解がすべての変数をカバーするよう、係数がゼロであっても、すべての変数に線形項が設定されます。

from qiskit_addon_opt_mapper import OptimizationProblem
from qiskit_addon_opt_mapper.converters import OptimizationProblemToQubo

def to_problem_dict(qubo: OptimizationProblem) -> dict[str, float]:
    """Convert a QUBO from OptimizationProblemToQubo to the SQOA Solver dictionary format."""
    objective = qubo.objective
    payload = {"()": objective.constant}
    # Keep every variable in the problem, even with a zero linear coefficient.
    payload.update({f"({i},)": 0.0 for i in range(qubo.get_num_vars())})
    for i, coefficient in objective.linear.to_dict().items():
        payload[f"({i},)"] += coefficient
    for (i, j), coefficient in objective.quadratic.to_dict().items():
        # Fold a binary diagonal term x_i * x_i = x_i into the linear term.
        key = f"({i},)" if i == j else f"({i}, {j})"
        payload[key] = payload.get(key, 0.0) + coefficient
    return {key: float(value) for key, value in payload.items()}

例 1: 3-正則グラフ上の MaxCut​

MaxCut のような多くのグラフ問題は NP 困難であり、量子最適化の自然な候補です。この例を実行するには、追加の依存関係として networkx をインストールします。

# %pip install networkx

1. モデルを記述する​

グラフ G=(V,E)G = (V, E)G=(V,E) の各頂点に二値変数 xv∈{0,1}x_v \in \{0, 1\}xv​∈{0,1} を割り当て、その頂点がカットのどちら側にあるかを示します。辺は、両端点が異なる側にあるときにカットされるため、カットサイズは次のとおりです。

Cut(x)=∑(u,v)∈E(xu+xv−2xuxv).\mathrm{Cut}(x) = \sum_{(u,v) \in E} \left(x_u + x_v - 2 x_u x_v\right).Cut(x)=(u,v)∈E∑​(xu​+xv​−2xu​xv​).

この目的関数は、制約のないそのままの QUBO なので、OptimizationProblemToQubo は最大化を等価な最小化に変えるだけで、変数はそのままです。qiskit_addon_opt_mapper.applications の Maxcut アプリケーションクラスを使うと、Maxcut(G).to_optimization_problem() で同じモデルを構築できます。

import networkx as nx

G = nx.random_regular_graph(3, 40, seed=42)

linear = {v: 0 for v in G.nodes}
quadratic = {}
for u, v in G.edges:
    linear[u] += 1
    linear[v] += 1
    quadratic[(u, v)] = -2

maxcut = OptimizationProblem("MaxCut")
maxcut.binary_var_list(G.number_of_nodes(), name="x")
maxcut.maximize(linear=linear, quadratic=quadratic)

2. ソルバーを実行する​

モデルを QUBO、さらに辞書に変換して送信します。problem と variable_type は必須です。backend_name は任意です。省略した場合や None の場合、関数はインスタンスで利用可能な、最も待ちの少ない稼働中の QPU を選択します。

options 辞書は、shots、seed、session、postprocessing_level、job_tags を受け付けます。説明とデフォルト値は、API リファレンスを参照してください。

qubo = OptimizationProblemToQubo().convert(maxcut)

job = solver.run(
    problem=to_problem_dict(qubo),
    variable_type="binary",
    backend_name="ibm_fez",
    options={
        "shots": 4096,
        "seed": 42,
    },
)

3. 結果を取得する​

job.result() は、4 つのキーを持つ辞書を返します。

  • solution は完全な変数の割り当てで、x_i をキーとします。i は変数のインデックスです (たとえば x_3)。

  • objective_value と feasible は、送信した辞書で評価した、その割り当ての目的関数値と実行可能性です。

  • metadata は solver_info と resource_usage を保持します。

QUBO は MaxCut の最小化形式であるため、objective_value はカットサイズの符号を反転した値です。カットサイズを直接読み取るには、元の OptimizationProblem で割り当てを評価します。

result = job.result()

x = [result["solution"][f"x_{i}"] for i in range(maxcut.get_num_vars())]
print(f"Cut value: {maxcut.objective.evaluate(x)}")
print(f"Nodes on side 1: {[v for v, value in enumerate(x) if value > 0.5]}")

4. リソース使用量を確認する​

result["metadata"]["resource_usage"] は、各実行フェーズで費やされた時間を報告します。RUNNING: EXECUTING_QPU 以外のフェーズは、利用可能な場合、そのフェーズの実時間 (秒) である CPU_TIME を報告します。

RUNNING: EXECUTING_QPU フェーズは、すべてのジョブで最終的な使用量が利用可能な場合、その実行におけるすべての Quantum Compute ジョブの QPU 使用量である QPU_TIME を報告します。詳細は、API リファレンスを参照してください。

for phase, metrics in result["metadata"]["resource_usage"].items():

    if "CPU_TIME" in metrics:

    if "QPU_TIME" in metrics:
        line += f" QPU {metrics['QPU_TIME']:8.1f} s"
    print(line)

例 2: 制約付き問題を QUBO に変換する​

SQOA Solver は制約なしの問題を受け付けます。この例では、OptimizationProblemToQubo で制約付き問題を QUBO に変換し、結果を元の問題の変数に対応付け直す方法を示します。

selection = OptimizationProblem("ConstrainedExample")
selection.binary_var_list(2, name="x")
selection.maximize(linear={"x0": 1, "x1": 1})
selection.linear_constraint({"x0": 1, "x1": 1}, "<=", 1, name="at_most_one")

print(selection.prettyprint())

    x0 x1

OptimizationProblemToQubo は、制約をペナルティ項として目的関数に加え、問題を最小化に変換します。適切なペナルティの重みは問題によって異なります。

実行後、interpret() は QUBO の割り当てを元の問題の変数に対応付け直します。

元の問題で目的関数値と実行可能性を評価します。辞書形式の問題では、辞書に制約がないため、結果の feasible フィールドは変数の定義域のみを指します。

converter = OptimizationProblemToQubo(penalty=4.0)
qubo = converter.convert(selection)

job = solver.run(
    problem=to_problem_dict(qubo),
    variable_type="binary",
    backend_name="ibm_fez",
)
result = job.result()

x_qubo = [result["solution"][f"x_{i}"] for i in range(qubo.get_num_vars())]
x = converter.interpret(x_qubo)
print("Objective:", selection.objective.evaluate(x))
print("Feasible:", selection.is_feasible(x))
print("x values:", x)
Objective: 1.0
Feasible: True
x values: [1. 0.]

例 3: OMMX インスタンスを送信する​

SQOA Solver は、OMMX SDK の ommx.v1.Instance も受け付けます。これは、変数名、添字、変換メタデータを問題とともに保持します。辞書と比べて、OMMX 入力には次の利点があります。

  • 結果には、solver_info["ommx_solution"] に正規の ommx.v1.Solution も含まれます。

  • objective_value はインスタンスの意味で評価されるため、最大化問題の目的関数は符号反転されません。

  • Instance.to_qubo() でその場で変換したインスタンスでは、feasible は元の制約に対して評価されます。

この例では、モデルを OMMX インスタンスにコンパイルする数理最適化モデラーである JijModeling を使って、例 1 の MaxCut モデルを構築します。JijModeling をインストールします。これにより ommx パッケージもインストールされます。

# %pip install "jijmodeling~=2.8.0"

SQOA Solver は、OMMX データを標準のパディング付き Base64 文字列としてやり取りします。この変換のために、次のヘルパー関数を定義します。

  • to_problem_payload() は、ommx.v1.Instance を、problem として渡す文字列にシリアライズします。

  • to_ommx_solution() は、結果から正規の ommx.v1.Solution をデコードします。

import base64

from ommx.v1 import Instance, Solution

def to_problem_payload(instance: Instance) -> str:
    """Serialize an OMMX instance into the `problem` string for SQOA Solver."""
    return base64.b64encode(instance.to_bytes()).decode()

def to_ommx_solution(result: dict) -> Solution:
    """Decode the canonical OMMX solution from a SQOA Solver result."""
    payload = result["metadata"]["solver_info"]["ommx_solution"]
    return Solution.from_bytes(base64.b64decode(payload, validate=True))

1. JijModeling でモデルを記述する​

グラフ G=(V,E)G = (V, E)G=(V,E) 上の MaxCut の一般的なスピン定式化では、各頂点に sv∈{−1,+1}s_v \in \{-1, +1\}sv​∈{−1,+1} を割り当てます。辺は susv=−1s_u s_v = -1su​sv​=−1 のときにカットされるため、カットサイズは次のとおりです。

Cut⁡(s)=∑(u,v)∈E1−susv2.\operatorname{Cut}(s) = \sum_{(u,v) \in E} \frac{1 - s_u s_v}{2}.Cut(s)=(u,v)∈E∑​21−su​sv​​.

JijModeling にはネイティブなスピン決定変数がなく、SQOA Solver は二値の QUBO 変数を受け付けます。そのため、bv∈{0,1}b_v \in \{0, 1\}bv​∈{0,1} を宣言し、モデルの中でスピン値の式 sv=1−2bvs_v = 1 - 2b_vsv​=1−2bv​ を定義します。この式により、目的関数は標準的なスピン形式のままとなり、 コンパイルされたインスタンスは二値の QUBO のままになります。

import jijmodeling as jm

@jm.Problem.define("MaxCut", sense=jm.ProblemSense.MAXIMIZE)
def maxcut_model(problem: jm.DecoratedProblem):
    V = problem.Natural()  # number of nodes
    E = problem.Graph(dtype=V)  # edge list
    b = problem.BinaryVar(shape=(V,))
    s = 1 - 2 * b  # spin-valued expression

    problem += jm.sum((1 - s[u] * s[v]) / 2 for u, v in E)

result = job.result()
