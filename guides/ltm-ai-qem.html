LTM による AI-QEM

API リファレンスを参照してください。

備考

IBM Quantum® Functions はベータ機能で、IBM Quantum Premium Plan、Flex Plan、On-Prem（IBM Quantum Platform API 経由）Plan のユーザーのみが利用できます。ベータ機能は変更されることがあります。

現在の制限事項

AI-QEM の現在のリリースには、次の制限事項があります。

  • エラー抑制は Heron プロセッサーファミリーに限定されています。 LTM は、今後のバージョンで追加のバックエンドをサポートする予定です。

  • エラー抑制は選択的に適用されます。 エラー抑制は、期待値の絶対値が ∣⟨O⟩noisy∣≥0.1|\langle O \rangle_{noisy}| \geq 0.1∣⟨O⟩noisy​∣≥0.1 を満たす場合にのみ実行されます。これにより、意味のある効果が見込まれる場合にのみエラー抑制が適用されます。

これらの制限事項は AI-QEM の現在の対象範囲を反映したものです。LTM が追加のワークフロー、バックエンド、機能のサポートを加えるにつれて、今後のリリースで緩和される可能性があります。

概要​

量子エラー抑制（QEM）には、ゼロノイズ外挿（ZNE）[2] や確率的エラーキャンセル（PEC）[3] などのアルゴリズム的プロトコルが含まれます。これらは、完全なフォールトトレランスに必要な大規模な量子ビットのオーバーヘッドを伴わずに、ノイズあり中規模量子（NISQ）ハードウェア上の期待値に生じるノイズ起因のバイアスを抑えるよう設計されています。これらの手法は、現在のプロセッサーから信頼できる物理シミュレーションやベンチマーク結果を得るうえで重要です。近年、多くの QEM 手法が開発されてきましたが、ほぼすべてが根本的なトレードオフを共有しています。精度を得るために QPU 時間を大幅に多く必要とするという点です。その決定的な制限は指数関数的なサンプリングオーバーヘッドです。ノイズのある回路からバイアスのない信号を再構成すると、推定量の統計的分散が大きく増加するためです。その結果、より高いノイズレベルを克服するには桁違いに多くの測定ショットが必要になり、QPU の実行時間が大幅に長くなり、ハードウェア上で深刻なボトルネックが生じます [4, 5, 6]。

AI-QEM を使用すると、ノイズのある QPU 上で量子回路を実行し、QPU の追加実行時間のオーバーヘッドなしに、他の AI ベースのエラー抑制手法よりも改善された期待値を得ることができます。このアプローチでは、グラフ畳み込みネットワーク（GCN）と Transformer を組み合わせたアーキテクチャのディープニューラルネットワークを使用します。このネットワークは、回路構造、バックエンドのトポロジー、パウリ観測量、量子ビットのキャリブレーションなどの特徴量で学習され、ζ\zetaζ で表される補正係数を予測します。ノイズありの期待値を ζ\zetaζ で割ることで、改善された期待値が得られます。実験では、AI-QEM が他の AI ベースの抑制手法よりも良い結果を出すことが示されています。特に、深さ（ゲート層）と幅（量子ビット数）が大きい回路で顕著であり、ユーティリティスケールの量子実験に適しています。ベンチマークセクションの表は、GCN-Transformer ベースのモデルが、80〜150 量子ビットの範囲でランダムフォレスト（RF）ベースのモデルを上回り、平均絶対誤差（MAE）が 0.343 であることを示しています。MAE とは、多数の回路と観測量の構成にわたる、理想的な期待値と、モデルがノイズのあるハードウェア結果を抑制した後の期待値との絶対差の平均です。さらに、このモデルは回路に依存しないため、回路固有のカスタマイズなしに、幅広い量子回路やアプリケーションに適用できます。

基盤となるコンポーネントの詳細な説明とユーティリティスケールのデモンストレーションについては、AI-QEM の論文 [1] を参照してください。

説明​

LTM AI-QEM function を使用して、特定の量子回路に対する観測量の期待値を推定します。LTM AI-QEM を使用するには、量子回路、測定する観測量のセット、QPU を指定します。この function は IBM Quantum Estimator プリミティブと同じ QPU 時間を使用し、追加の QPU 時間は必要ありません。

観測量 OOO の期待値を計算する通常の方法は、観測量をパウリ演算子の和 O=∑iciPiO=\sum_i{c_i}{P_i}O=∑i​ci​Pi​ に分解し、各パウリ演算子の期待値 ⟨Pi⟩\langle P_i \rangle⟨Pi​⟩ を個別に計算することです。観測量の期待値 ⟨O⟩\langle O \rangle⟨O⟩ は、パウリ期待値の同じ線形結合になります: ⟨O⟩=∑ici⟨Pi⟩{\langle O \rangle}=\sum_i{c_i}{\langle P_i \rangle}⟨O⟩=∑i​ci​⟨Pi​⟩。パウリ演算子の集合が互いに可換である場合、それらの期待値の計算に必要な測定を同時に行うことができます。LTM AI-QEM function で回路を実行すると、この function は Estimator プリミティブを使用して、通常どおりハードウェア上で回路を実行します。観測量をパウリ演算子に分解し、それらの期待値を個別に計算する手順も同じです。その後、ディープラーニングアーキテクチャである GCN-Transformer が、各パウリ演算子 PiP_iPi​ に対する補正係数 ζi\zeta_iζi​ を予測します。この function は、この補正係数を使用して各パウリ演算子のノイズありの期待値を補正します: ⟨Pi⟩mitigated=⟨Pi⟩noisyζi{\langle P_i \rangle}_{mitigated} = \frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}⟨Pi​⟩mitigated​=ζi​⟨Pi​⟩noisy​​。したがって、抑制後の期待値は ⟨O⟩mitigated=∑ici⟨Pi⟩mitigated=∑ici⟨Pi⟩noisyζi{\langle O \rangle}_{mitigated} = \sum_i{c_i}{\langle {P_i} \rangle}_{mitigated} = \sum_i{c_i}{\frac{{\langle P_i \rangle}_{noisy}}{\zeta_i}}⟨O⟩mitigated​=∑i​ci​⟨Pi​⟩mitigated​=∑i​ci​ζi​⟨Pi​⟩noisy​​ となります。

LTM AI-QEM function を使用するワークフローは次のとおりです。

  1. 回路と観測量を定義します。

  2. 回路と観測量のペアをプリミティブ統合ブロック（PUB）として渡し、LTM AI-QEM function を実行します。

  3. 結果を取得します。結果には、各 PUB の対応する量子回路に対する観測量の期待値が含まれます。

多くのテスト例から、LTM AI-QEM function が観測量の推定を改善することが経験的に示されています。この function には次の特長があります。

  • ユーティリティスケールの実験: テスト例では、深さと幅の大きい回路において、AI-QEM が他の AI ベースの手法よりも優れた性能を示しています。結果についてはベンチマークセクションを参照してください。

  • プリミティブ: この function は Estimator プリミティブをサポートしているため、任意の量子回路に対する任意の観測量の期待値を計算できます。

  • プリミティブ統合ブロック（PUB）: LTM AI-QEM function は、Estimator プリミティブがサポートするすべてのタイプの PUB（つまり、すべての回路と観測量の構成）をサポートします。

AI-QEM 手法は、データセットの構築から始まります。ここでは、さまざまなパラメーター設定でランダムな量子回路が生成されます。各回路について、理想的な期待値（シミュレーションで取得）とノイズありの期待値（ハードウェアでの実行で取得）の両方が計算されます。これらの結果は、対応する量子回路とバックエンド情報とともに、データセットリポジトリに保存されます。その後、このデータセットを使用して、量子計算のノイズを抑制できる機械学習またはディープラーニングのモデルを学習し、学習済みモデルは将来の使用のために保存されます。推論時には、学習済みモデルは、量子回路、ハードウェアで計算されたそのノイズありの期待値、関連する観測量、バックエンド情報を入力として受け取ります。モデルはこれらの入力を処理して、ノイズを抑制した期待値を出力します。

サポート​

AI-QEM サポートチームがお手伝いします。問題が発生した場合、AI-QEM Function の使用方法について質問がある場合、またはジョブのトラブルシューティングについてサポートが必要な場合は、サポートチームにお問い合わせください。

サポート: quantumfunction.support@ltm.com

サポートチームが問題をできるだけ早く調査して解決できるよう、サポートリクエストに次の情報を含めてください。

  • Function のジョブ ID（例: job.job_id）

  • 問題の詳細な説明

  • 関連するエラーメッセージ、スタックトレース、エラーコード

  • 期待される動作と実際の動作（該当する場合）

情報が揃っていると、サポートチームがより効率的に問題を診断し、より迅速に解決できます。

AI-QEM サポートチームは、フィードバックや機能のリクエストも歓迎します。改善のご提案や、今後のリリースで利用したい機能がありましたら、quantumfunction.support@ltm.com までお送りください。
