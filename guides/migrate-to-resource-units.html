IBM Quantum Compute API でのリソース単位（RU）への移行

IBM Quantum® Platform では、使用量をリソース単位（RU）で計測するようになりました。RU は、IBM Quantum がすべてのワークロードの使用量を計測し課金するために使用する単位です。この変更の前は、プラットフォームは使用量を QPU 時間（秒またはミリ秒）として計測していました。RU の詳細については、リソース単位を参照してください。

現在、API は古い時間フィールドと新しい RU フィールドの 2 組のフィールドを返します。既存の統合は引き続き動作します。将来のリリースで、IBM Quantum は時間フィールドを削除します。今のうちに、RU フィールドを読み取るように統合を変更してください。

このガイドでは次の用語を使用します。

  • ワークロード: ジョブ、セッション、バッチ、または function の実行。

  • QPU ワークロード: ジョブ、セッション、またはバッチ。QPU ワークロードは QPU 上でのみ実行されます。

  • Function ワークロード: function の実行。Function ワークロードでは、古典コンピュートと実行ライセンスを使用でき、QPU も使用できます。

  • セッション: 1 つの QPU 上でまとめて実行されるジョブのグループ。

  • インスタンス: サービスインスタンス。ワークロードを所有し、使用制限を持ちます。

  • プラン: アカウントのサービスプラン。アカウント内のすべてのインスタンスの使用制限を設定します。

備考

このガイドでは、OpenAPI 仕様のバージョン 0.57.2 を使用します。

IBM-API-Version ヘッダーの値は、2026-04-15 またはそれ以降のサポートされている API バージョンである必要があります。

概要​

エンドポイント無視するフィールド代わりに読み取るフィールド
GET /v1/jobs, GET /v1/jobs/{id}/metricsusage.qpu_charge_time_secondsusage.value
GET /v1/workloadsworkloads[].usage.qpu_charge_time_secondsworkloads[].usage.value
POST /v1/sessions, GET /v1/sessions/{id}elapsed_timeusage.value
GET /v1/instances/usageusage_consumed_seconds, usage_limit_seconds, usage_allocation_secondsusage_consumed_ru, usage_limit_ru, usage_allocation_ru
GET /v1/accounts/{id}plans[].usage_limit_seconds, plans[].usage_allocation_seconds, plans[].unallocated_usage_secondsplans[].usage_limit_ru, plans[].usage_allocation_ru, plans[].unallocated_usage_ru
Resource Controller API: サービスインスタンスの作成、更新、読み取りinstance_limit_seconds, usage_allocation_secondsinstance_limit_ru, usage_allocation_ru
GET /v1/analytics/usage, GET /v1/analytics/usage_grouped, GET /v1/analytics/usage_grouped_by_dateミリ秒単位の各使用量フィールド接尾辞 _ru が付いた対応するフィールド

以降のセクションでは、各エンドポイントの詳細を説明します。

ジョブ​

エンドポイント: GET /v1/jobs および GET /v1/jobs/{id}/metrics。

無視するフィールド代わりに読み取るフィールド
usage.qpu_charge_time_secondsusage.value

usage オブジェクトには次のフィールドもあります。

  • usage.unit: usage.value の単位。値は常に "resource_units" です。

  • usage.status: 課金ステータス。値は "pending" または "complete" です。ステータスが "pending" の場合、プラットフォームが値をまだ変更する可能性があります。保留中の値を最終的な使用量として使用しないでください。

  • usage.details[]: 課金メトリックごとの使用量。各エントリーの value は RU で表されます。

Example:

"usage": {
  "qpu_charge_time_seconds": 15,  // old field: disregard
  "value": 0.250005,              // new field: read this
  "unit": "resource_units",
  "status": "complete",
  "details": [
    { "value": 0.250005, "unit": "resource_units", "metric": { "id": "…", "value": 15 } }
  ]
}

フィールド usage.details[].metric.value は RU での使用量ではありません。これは、プラットフォームが RU を計算するために使用したメトリックの量です。各メトリックには固有の単位があります。たとえば、QPU メトリックの単位は秒です。使用量を取得するには、usage.details[].value を読み取ってください。

ワークロード​

Endpoint: GET /v1/workloads.

workloads[] の各項目には usage オブジェクトがあります。このオブジェクトには、ジョブの usage オブジェクトと同じフィールドがあります。

無視するフィールド代わりに読み取るフィールド
workloads[].usage.qpu_charge_time_secondsworkloads[].usage.value

ワークロードがまだ実行中の場合、usage は null です。

Function ワークロード​

function ワークロードの使用量は、QPU ワークロードと同様に RU で表されます。function ワークロードは複数のメトリックを使用することがあります。

  • QPU 使用量。 量子時間の秒ごとに計測されます。実行モードを参照してください。

  • 古典コンピュートの使用量。 古典時間の秒ごとに計測されます。

  • 実行ライセンスのコスト。 function に渡される問題のサイズに基づいて、ワークロードごとに計測されます。

プラットフォームは、各メトリックの量を RU に変換します。したがって、すべての使用量の値は RU で表されます。

  • usage.value は、ワークロードの使用量を RU で表したものです。

  • usage.details[].value は、1 つのメトリックの使用量を RU で表したものです。

  • usage.details[].metric.value は、メトリックの量をそのメトリックの単位で表したものです。RU ではありません。

使用量の値を表示または合計する場合は、usage.value と usage.details[].value を使用してください。usage.details[].metric.value は使用しないでください。

セッション​

エンドポイント: POST /v1/sessions および GET /v1/sessions/{id}。

無視するフィールド代わりに読み取るフィールド
elapsed_time（秒）usage.value

セッションの usage オブジェクトには unit と details[] があります。これらのフィールドは、ジョブの usage オブジェクトと同じように動作しますが、status フィールドはセッションでは省略されます。

フィールド interactive_ttl、max_ttl、active_ttl は変更されません。これらは使用量ではなく、時間制限です（TTL は「time to live」の意味）。単位は引き続き秒です。

インスタンスの使用量​

Endpoint: GET /v1/instances/usage.

無視するフィールド代わりに読み取るフィールド
usage_consumed_secondsusage_consumed_ru
usage_limit_secondsusage_limit_ru
usage_allocation_secondsusage_allocation_ru

フィールド usage_limit_reached、usage_period、time_available_at は変更されません。

アカウントのプラン​

Endpoint: GET /v1/accounts/{id}.

plans[] の各項目には次の変更があります。

無視するフィールド代わりに読み取るフィールド
plans[].usage_limit_secondsplans[].usage_limit_ru
plans[].usage_allocation_secondsplans[].usage_allocation_ru
plans[].unallocated_usage_secondsplans[].unallocated_usage_ru

Resource Controller API のサービスインスタンス​

IBM Cloud® Resource Controller API は別の API です。これを使用してサービスインスタンスを作成および更新します。この API でインスタンスを作成または更新する場合は、インスタンスのパラメーターも変更してください。

インスタンスを作成または更新するときは、リクエストで次のパラメーターを送信します。

送信しない代わりに送信する新しいパラメーターの型
instance_limit_secondsinstance_limit_ru数値または null
usage_allocation_secondsusage_allocation_ru数値または null

各パラメーターの意味は次のとおりです。

  • インスタンスの制限インスタンスの最大使用量。Open Plan で制限を送信しない場合、デフォルトは 10 分に相当する RU です。

  • 使用量の割り当て: インスタンスの使用量の割合。フェアシェアスケジューラーは、この値を使用してキュー内のインスタンスの優先順位を設定します。割り当ては従量課金（Pay-As-You-Go）のインスタンスには適用されません。

インスタンスを読み取ると、レスポンスの extensions オブジェクトには古いフィールドと新しいフィールドが含まれます。instance_limit_seconds と usage_allocation_seconds は無視してください。instance_limit_ru と usage_allocation_ru を読み取ってください。

詳細については、IBM Quantum Compute Service REST API ドキュメントを参照してください。

使用量アナリティクス​

エンドポイント: GET /v1/analytics/usage、GET /v1/analytics/usage_grouped、GET /v1/analytics/usage_grouped_by_date。

3 つのエンドポイントには同じ使用量フィールドがあります。2 つのグループ化されたエンドポイントは、グループごとまたは日付ごとにこれらのフィールドを返します。

古いアナリティクスの使用量フィールドは、秒ではなくミリ秒単位です。

無視するフィールド（ミリ秒）代わりに読み取るフィールド（RU）
usageusage_ru
sessions_usagesessions_usage_ru
avg_sessions_usageavg_sessions_usage_ru
max_sessions_usagemax_sessions_usage_ru
batch_sessions_usagebatch_sessions_usage_ru
avg_batch_sessions_usageavg_batch_sessions_usage_ru
max_batch_sessions_usagemax_batch_sessions_usage_ru
dedicated_sessions_usagededicated_sessions_usage_ru
avg_dedicated_sessions_usageavg_dedicated_sessions_usage_ru
max_dedicated_sessions_usagemax_dedicated_sessions_usage_ru
individual_jobs_usageindividual_jobs_usage_ru
avg_individual_jobs_usageavg_individual_jobs_usage_ru
max_individual_jobs_usagemax_individual_jobs_usage_ru
functions_quantum_usage_msfunctions_quantum_usage_ru

次の function フィールドは新しいものです。ミリ秒単位の古いフィールドはありません。

  • functions_usage_ru

  • avg_functions_usage_ru

  • max_functions_usage_ru

  • functions_classical_usage_ru

  • functions_license_cost_ru

usage_ru の合計には、usage の合計よりも多くのものが含まれます。

  • usage は、セッション、個別のジョブ、function の QPU 時間の合計です。

  • usage_ru は、セッション、個別のジョブ、function の使用量の合計です。function の場合は、古典コンピュートとライセンスのコストも含まれます。

したがって、usage_ru は単に usage を別の単位で表したものではありません。

フィールド queue_time、avg_queue_time、max_queue_time は変更されません。これらは使用量ではなく待機時間を測定します。単位は引き続きミリ秒です。

変更されないフィールド​

これらのフィールドには時間の値が含まれますが、使用量を測定するものではありません。IBM Quantum はこれらを置き換える予定はありません。

  • バックエンドの wait_time_seconds: キューでの推定待機時間。

  • GET /v1/jobs/{id}/metrics の circuits_execution_time_ns: ジョブが QPU 上で実行された時間。

  • セッションの interactive_ttl、max_ttl、active_ttl。

  • アナリティクスの queue_time、avg_queue_time、max_queue_time。

  • バックエンド設定の rep_times と circuit_duration。

移行の手順​

  1. コード内の古いフィールドをすべて見つけます。qpu_charge_time_seconds、elapsed_time、このガイドの _seconds フィールド、およびミリ秒単位のアナリティクスフィールドを検索してください。

  2. 古いフィールドを、このガイドの表にある RU フィールドに変更します。

  3. Resource Controller API でサービスインスタンスを作成または更新する場合は、instance_limit_ru と usage_allocation_ru を送信します。_seconds パラメーターは送信しないでください。

  4. ユーザーインターフェースのラベルを変更します。「秒」や「分」ではなく、「RU」または「リソース単位」と表示してください。RU を時間に換算しないでください。RU と時間の間に固定レートはありません。

  5. usage.details[] を読み取る場合は、RU での使用量として value を使用します。metric.value の単位はメトリックの単位であるため、使用しないでください。

  6. usage.status が "pending" の場合は、値を暫定値として表示します。

  7. RU フィールドが存在しないか null の場合は、現在古いフィールドに使用しているのと同じロジックを使用します。
