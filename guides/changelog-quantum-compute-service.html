IBM Quantum Compute Service

IBM Quantum® Compute Serviceの最新のパッケージリリースの概要とプラットフォームの更新情報はこのページでご確認いただけます。

2026年9月​

  • 最初のNighthawk r2 QPUが利用可能になりました — Premium、Flex、Pay-As-You-Go Planで、最初のIBM Quantum Nighthawk r2 QPUであり、これまでで最速のプロセッサーであるibm_phoenixにアクセスできるようになりました。ibm_phoenixは高接続性を持つ正方格子構造の120プログラマブルQubitデバイスであり、Heronと同等の忠実度を維持しながら最大25倍のスループットを実現します。

    この向上は、すべてのプログラマブルQubitをより速く、より完全に基底状態に戻す新しい独立した高速リセット機能によるものです。その結果、デフォルトの繰り返し遅延は1µs(以前は250µs)となり、スループットは毎秒100,000 Max Circuits Per Second(MCPS)を超えるようになりました。IBMが規模、品質、速度の指標にわたって量子ハードウェアのパフォーマンスをどのように追跡しているかについて詳しくは、こちらのブログをご覧ください。

    速度と接続性の向上により、同じ容量でより多くの実用的な作業を行うことが可能になり、最大かつ最も要求の厳しいワークロードが最も恩恵を受けます。かつて大規模には実行コストが高すぎたより大きな実験、より広範なパラメータスイープ、および手法が、日常的に実行可能になります。

    ibm_phoenixは、量子誤り訂正研究の次の時代のためにも構築されています。高速リセットに加えて、誤り訂正のリアルタイム制御のためのmid-circuitリセットとダイナミック回路をサポートしています。

2026年8月​

  • IBM Quantum Platformの更新 — IBM Quantum Platformの最近の更新により、ジョブ結果の理解が容易になり、Composerで強力な新しい回路設計機能が利用できるようになり、使用制限についての情報が常に得られるようになりました。これにより、量子研究により集中できます。

    • ジョブ結果とワークロード

      • ビット単位の結果表示 — Samplerの測定結果を表示する新しい方法で、完全な状態ごとではなくビットごとに結果を分解します。結果に多くの異なる状態が含まれる場合、Measurement outcomesビューの代替として便利です。

      • Circuit タイミング・チャート — Circuit の操作(ゲート、チャネル、期間)のスケジュールされたタイムラインを表示します。Sampler および Executor ジョブで利用可能です。タイミングデータの取得を有効にすることが必要です。

      • チャンク/スパン実行診断パネル — チャンクおよびスパンレベルの実行診断を表示する、ジョブ詳細の新しいパネルです。このデータの意味とジョブ送信時の有効化方法については、Sampler の入出力を参照してください。

      • デバイス・キャリブレーション・データを一目で確認 — ジョブ詳細に、送信時または実行時のデバイス・キャリブレーション・データが「キャリブレーション履歴を表示」リンクから表示されるようになりました。

      • Executor 結果の可視化 — ジョブ詳細ページで Executor ジョブの結果がレンダリングされるようになりました。Executor の詳細については、Directed execution model (ベータ) ガイドを参照してください。

      • 動的 Circuit がジョブ詳細でレンダリングされるようになりました — Composer での OpenQASM 3.0 サポート(詳細は以下を参照)により、これまでレンダリングに失敗していた Circuit(動的 Circuit を使用するものなど)が、ジョブ詳細ページで正しく表示されるようになりました。

      • ヒストグラムの改善 — 読み込みの高速化、ズームイン/アウトの滑らかさの向上、特定の結果範囲を絞り込むための新しい選択ツールが追加されました。

      • ジョブ結果内の qiskit-ibm-runtime コード・スニペット — ID でジョブを取得するためのコピーして使えるコードです。Executor ジョブの場合は、そのジョブを再現するための追加スニペットも用意されています。

      • ワークロード・テーブルにカスタム日付範囲フィルターが追加されました。

      • ワークロード詳細ページのクリック可能なインスタンス名とタグが、関連リソースにリンクします。

      これらの改善内容を確認するには、Workloads ページで結果を確認してください。

    • Composer: OpenQASM v3.0 サポート

      Composer が OpenQASM v3.0 をサポートするようになり、以下が追加されました。

      • Gate 修飾子 — ctrl、inv、pow など。

      • ループ — for および while

      • 条件ロジック — if/else

      • ボックス注釈 — Circuit のセクションをグループ化してラベル付け

      また、大規模な Circuit のレンダリングの滑らかさの向上と、大規模な Circuit で PNG エクスポートが失敗する不具合の修正も含まれています。

    この新しいアップデートを確認するには、Composer にアクセスしてください。

    • インスタンス使用量制限

      • 使用量制限に達した Premium プランおよび Open プランのインスタンスでは、ローリング使用ウィンドウに基づいて、アクセスが再開される正確な日付が表示されるようになりました。

    詳細は Instances ページをご覧ください。

2026年7月​

Qiskit Runtime の名称変更​

  • Qiskit Runtime サービスは IBM Quantum Compute Service になりました — これは名称変更のみであり、コードの変更や既存アプリケーションの更新は必要ありません。ユーザーインターフェースやドキュメント全体で新しい名称に気付くかもしれません。

    これまで、Qiskit Runtime という用語は、関連はあるものの異なる3つの概念を指すために使用されてきました。

    Qiskit ユーザーが自社の量子コンピューター上でワークロードを実行できるようにしたいハードウェア・プロバイダーは、プロバイダー固有の2つのコンポーネントを提供する必要があります。

    • ユーザーがプロバイダーにジョブを送信できるようにする Qiskit SDK 拡張機能。IBM の場合、これはオープンソースの qiskit-ibm-runtime ライブラリです。量子コンピューターと直接通信するのではなく、クラウド API にジョブを送信します。

    • 量子コンピューター自体で実行されるランタイム実行環境。このコンポーネントは Qiskit プリミティブを理解し、それらをハードウェア固有の操作に変換して、量子ハードウェア上で実行します。IBM の場合、これは IBM Qiskit Runtime です。

    この2つのコンポーネントの間には、3つ目の要素があります。それは、qiskit-ibm-runtime SDK からジョブを受け取り、その実行をオーケストレーションするマネージド・クラウド・サービスです。このサービスは、認証、スケジューリング、キュー管理、ワークロードのルーティング、使用量の追跡、制限、分析などの機能を担います。Qiskit プリミティブ自体を処理するのではなく、適切な量子コンピューターにワークロードをディスパッチし、そこでランタイム実行環境が実際の実行を行います。

    これまで、このクラウド・サービスはランタイム自体とは概念的に異なるにもかかわらず、Qiskit Runtime Service とも呼ばれてきました。このように Qiskit Runtime という用語が実行環境とマネージド・クラウド・サービスの両方を表すために二重に使用されたことで、アーキテクチャが不明瞭になり、オープンソース・コンポーネントとマネージド・クラウド・サービスを区別することが難しくなっていました。

    Qiskit Runtime Service を IBM Quantum Compute Service に改名することで、この曖昧さが解消されます。その結果、アーキテクチャは非常に明確になります。

    • qiskit-ibm-runtime: ワークロードを送信するオープンソースの Qiskit 拡張機能。

    • IBM Quantum Compute Service: ワークロードの認証、スケジューリング、管理、ルーティングを行うマネージド・クラウド・サービス。

    • IBM Qiskit Runtime(または IBM Qiskit Runtime Execution Environment): 量子コンピューター上で実行され、Qiskit プリミティブを処理・実行する実行環境。

2026年5月​

Store 命令​

  • IBM® QPU での Store 命令のサポート - Store 命令を使用して、量子 Circuit 内の複雑な古典計算を簡素化できるようになりました。

    • Circuit の途中で古典的な式を計算し、その結果を変数またはレジスターに保存することで、後続の量子 Gate を直ちに制御できます。深くネストしたインライン式の代わりに、計算を名前付きの中間ステップに分割できるため、複雑な古典フィードバック・ロジックの可読性と保守性が向上します。一般的なユース・ケースには、以下が含まれます。

      • Circuit 途中の測定と古典フィードバックを伴う動的 Circuit

      • 長距離もつれの準備

      • 測定結果に基づく複雑な条件ロジック

      store 命令を使用するには、まず qiskit-ibm-runtime の最新バージョンを実行していることを確認し(pip install --upgrade qiskit-ibm-runtime)、詳細と例については ドキュメント を参照してください。

      ジョブを送信する前に、ドキュメントで各プリミティブのオプションとの互換性を確認する必要があることに注意してください: Sampler オプション | Estimator オプション | Executor オプション

    Qiskit Code Assistant サービスの提供終了予定​

    2026年5月29日、IBM Quantum はプレビュー版の Qiskit Code Assistant サービスを終了し、Visual Studio Code および JupyterLab 用のサポート拡張機能をアーカイブします。

    フィードバックと使用状況のパターンに基づき、より多くのユーザーが Qiskit Code Assistant モデルをローカルで実行し、開発ワークフローに既に組み込まれているエディター統合機能を利用しています。

    Qiskit Code Assistant モデルは、ローカルでの使用については引き続き利用可能です。使用を継続するには、ローカル・デプロイメントとコミュニティによってサポートされるエディター統合機能、またはその他のローカル・ツールに移行してください。

    セットアップ手順については、Qiskit Code Assistant ガイドを参照してください。

    Nighthawk が EU に登場​

    Premium プランおよび Flex プランで、ibm_berlin への早期アクセスが可能になりました！これは EU(eu-de リージョン)で最初の IBM Quantum Nighthawk r1 QPU であり、米国(us-east リージョン)の ibm_miami に続く、グローバル・フリート内で2番目の Nighthawk です。ibm_berlin は、ibm_miami よりも高速な2量子ビット Gate を備えており(中央値で 68 ns 対 138 ns)、フリート最高水準のコヒーレンス(T1_11​ 約350 µs)を維持しています。

    リリース以来、Nighthawk は古典シミュレーションがますます困難になる領域での研究を可能にしてきました。特に、そのアーキテクチャは、グリッドベース(格子)モデルに自然に対応するハードウェア効率的なワークフローをサポートします。Nighthawk 上での大規模シミュレーションを実証する、Phasecraft や Volkswagen およびその共同研究者による最近の論文をご覧ください。

    ibm_berlin は現在、継続的な学習サイクルの一環としてテストと最適化が続けられている探索的な QPU であることにご注意ください。そのため、一時的に以下の制限があります。

    • デフォルトの繰り返し時間が、250 µs から 4 ms に一時的に延長されており、これによりワークロードの実行に必要な QPU 時間に影響が及びます。ユーザーは手動でより短い繰り返し時間を選択できますが、パフォーマンスが低下する可能性があります。

    • 動的 Circuit はまだサポートされておらず、Circuit 途中の測定の品質は限られています。

    今後の退役予定​

    EU での容量拡大と最新の Nighthawk および Heron プロセッサーの展開に伴い、ibm_brussels と ibm_strasbourg は2026年4月30日前後に退役する予定です。

    これらの QPU が退役すると、ジョブを受け付けなくなります。ワークフローが ibm_brussels または ibm_strasbourg を対象としている場合は、最新のシステムを活用するために、退役日より前に別の稼働中の QPU に移行してください。過去のジョブからデータを取得する方法については、次のドキュメントを参照してください。

    ibm_torino が退役しました​

    量子コンピューター ibm_torino は退役し、ワークロードの送信を受け付けなくなりました。この QPU で既にキューに入っていたワークロードは、引き続き処理され結果が返される場合があります。

    この QPU で実行された重要なワークロードのジョブ・データを取得したい場合は、こちらの手順を参照してください。

    ibm_brussels と ibm_strasbourg が退役しました​

    ibm_brussels と ibm_strasbourg は退役し、ジョブを受け付けなくなりました。

    この変更は、最近リリースされた Nighthawk QPU の ibm_berlin や、アップグレードされた Heron r3 QPU の ibm_aachen を含む、EU における IBM Quantum フリートの継続的な進化と拡大の一環です。グローバル・フリートは、2021年に導入された IBM Quantum 初のユーティリティ・スケール・プロセッサー・ファミリーである Eagle から完全に移行しました。

    ワークフローが ibm_brussels または ibm_strasbourg を対象としている場合は、最新のハードウェアを活用するために別の稼働中の QPU に移行してください。過去のジョブからデータを取得する方法については、ドキュメントを参照してください。

2026年3月​

EU に初の Heron r3 が登場​

ibm_aachen のメンテナンスが完了し、この QPU は eu-de リージョンで再びオンラインになりました。ibm_aachen はまた、最新の Heron r3 プロセッサーを搭載した EU 初の QPU にアップグレードされました。これは、米国の ibm_boston と ibm_pittsburgh に続く、グローバル・フリートで3番目の r3 です。

Heron r3 は、Heron r2 と比較してエラー率とシステム全体のパフォーマンスの向上を引き続き実現しており、ワークロードに対してより信頼性の高い実行と優れた結果を示しています。例えば ibm_aachen では、T2T_2T2​(位相コヒーレンス時間)が 150 µs から 250 µs へと大幅に向上していることが確認されています。共有フリート内のすべての QPU について、このようなメトリクスは Compute resources ページでご覧いただけます。

2026年2月​

ibm_torino to retire​

ibm_torino QPU は、2026年4月1日前後に退役します。この QPU が退役すると、ジョブを受け付けなくなります。

重要な過去のジョブからジョブ・データを取得したい場合は、次のドキュメントを参照してください。

繰り返し遅延時間の最大値の引き上げ​

ユーザーの柔軟性を高めるため、Heron および Eagle QPU での許容される繰り返し遅延時間の範囲を、20〜500 µs から 20〜2000 µs に拡張しました。Nighthawk QPU の遅延時間範囲は、以前発表された通り 1000〜4000 µs のままです。繰り返し遅延(rep_delay)を増やすことを選択した場合、実行時間と容量消費に直接影響しますが、特定の Circuit の忠実度が向上する可能性があることにご注意ください。デフォルトの rep_delay はすべての QPU で変更されていません。

繰り返し遅延時間の変更方法を含む詳細情報については、Qubit の初期化を参照してください。

  • 初の Nighthawk QPU と最新の Heron QPU が利用可能になりました。 これら2つの強力な新プロセッサーは、11月の IBM Quantum Developer Conference でデビューしました。

    • Premium プランおよび Flex プランで、最初の IBM Quantum Nighthawk QPU である ibm_miami への早期アクセスが可能になりました。これまでで最も高度な量子プロセッサーである Nighthawk は、正方格子トポロジー(Heron の176に対して218カプラー)を備えた120量子ビットのデバイスであり、より複雑なワークロードをサポートするよう設計されています。Nighthawk は、QDC で報告された値をも上回る、フリート最高のコヒーレンスを備えており、中央値 T1 は350 µs です。

    • ibm_miami は現在、継続的な学習サイクルの一環としてテストと最適化が続けられている探索的な QPU であることにご注意ください。そのため、一時的に以下の制限があります。

      • デフォルトの繰り返し時間が、250 µs から 4 ms に一時的に延長されており、これによりワークロードの実行に必要な QPU 時間に影響が及びます

      • 動的 Circuit はまだサポートされておらず、Circuit 途中の測定の品質は限られています

    • さらに、Premium プラン、Flex プラン、および Pay-As-You-Go プランで、これまでで最も高性能な IBM Quantum Heron r3 である ibm_boston へのアクセスが可能になりました。これは、100量子ビットで EPLG 2.15e-3 を達成しており、176通りの可能な2量子ビット Gate のうち57が 1e-3 未満のエラー・レベルを示しています。

  • IBM Quantum Platform の管理者向けにインスタンス・アーカイブ機能を導入しました。 このアップデートにより、管理者はアカウント内の任意のインスタンスをアーカイブできるようになりました。インスタンスをアーカイブすると、以下が保証されます。

    • 共同作業者は、過去のワークロードの結果や QPU のメトリクス、プロパティ、キャリブレーションへのアクセスを引き続き保持します。

    • アーカイブされたインスタンスには新しいワークロードを送信できなくなり、意図しない使用を防ぎます。

    • アーカイブされたインスタンスは、アカウントのプラン割り当てから何も差し引きません。

    • アーカイブされたすべてのインスタンスは、専用の「Archived」タブの下に整理されます。

    • 管理者はいつでもインスタンスを再有効化できます。

  • Directed execution model。 この新しい実行モデルでは、設計意図をクライアント側で捉えるための要素を提供し、コストの高い Circuit バリアントの生成をサーバー側にシフトすることで、パフォーマンスを犠牲にすることなくエラー抑制などの手法を微調整できます。例えば、Samplomatic ライブラリーを使用して、Circuit 内の Pauli-twirling を適用しノイズを注入する正確なレイヤーを定義できます。その後、新しい Executor プリミティブは、その指示に従って、Qiskit Runtime でランダム化された Circuit バリアントを生成・実行します。

IBM Quantum Network限定：私たちの製品とサービスにおける最新の進展を発表し、パートナーのユース・ケースを紹介し、量子の専門家との質疑応答の機会を提供する初のIBM Quantum Product Updates Webinarシリーズに、ぜひご参加ください。

最初のセグメントでは、セキュリティ、安定性、ユーザー・エクスペリエンスの向上を目的としたIBM Quantum Platformの進化についてお話しします。チームが主要な更新内容を説明し、新機能をデモンストレーションし、これらの改善が開発者やユーザーにどのような力を与えるかについて議論します。

2番目のセグメントでは、Qiskit Functions Catalogに追加される3つの新しく革新的なQiskit Functionsのローンチを取り上げます。各Function提供者が自社のソリューションを発表し、その独自の機能、ユース・ケース、より広いエコシステムへの影響を紹介します。参加者は、これらのQiskit Functionsが実世界のアプリケーションでどのように活用できるかについて、直接的な知見を得ることができます。

詳細を確認して今すぐ登録する

2025年2月26日​

  • 本日、アップグレードされたエクスペリエンスの早期アクセス版をリリースします。ぜひアカウントを開設して新しいインターフェースを試してください。今後数か月にわたって引き続きアップデートを展開し、最終的にはIBM Quantum Platform Classicのクラシック版のような見た目と操作感を持ちながら、より高い機能性を備えたエクスペリエンスの実現を目指します。IBM Quantum Platform Classicは最終的に終了しますので、今後の更新情報にご注目ください。

  • ご注意ください：IBM Quantum Platformへのアクセスがプラン管理者（Premium Plan、On-Prem Plan、Startup Programなど）の管理下にある場合、今後数か月のうちに管理者を通じてガイド付きの移行サポートを受けることになります。それまでの間、無料のOpen Planアカウントを作成して新しいプラットフォームを試すことができます。

  • 早期アクセス・リリースおよび今後の改善に関する詳細は、ブログを確認してください。

2025年2月24日​

インベントリを刷新するにあたり、以下のQPUを2025年4月18日前後に廃止します。

  • ibm_kyiv

  • ibm_sherbrooke 更新：ibm_sherbrookeは2025年4月18日以降も数週間、稼働を継続します。

これらのQPUが廃止される前に、重要な過去のジョブのジョブ・データを必ず取得してください。

2025年2月3日​

  • すべてのIBM量子プロセッサーでパルスレベルの制御が削除されました。さらに、パルス・モジュールはQiskit SDK v2.0で削除される予定です。代わりに、命令セット・アーキテクチャ（ISA）に組み込まれた分数ゲートを使用できます。詳細およびコードの移行に関するヘルプは、Qiskit Pulseから分数ゲートへの移行を参照してください。

2025年2月2日​

  • 2025年6月2日から始まり、年内を通じて、IBM Quantumは動的回路の新機能をユーティリティ・スケールで有効化するために、段階的な展開を開始します。 改善内容は以下のとおりです。

    • Gen3エンジン・スタックの使用による実行速度75倍の向上

    • ブランチの並列実行により、回路の実行時間が短縮され、結果の品質が向上

    • 回路途中測定の改善

    • 動的デカップリングとのより良い統合

    • 回路タイミング情報の可視性の向上

  • 展開を加速するため、以下の機能は非推奨となり、2025年6月2日前後にサポートが終了します。

    • while、for、switch制御フロー構造

    • 分岐の本体内で制御フロー命令を使用する機能（つまり、ネストされた制御フロー）

    • 条件付き測定

2025年1月7日​

  • 本日よりGen3エンジンスタックの展開が開始されます。このエンジンスタックにより、実行速度が75倍向上します。展開はQPUごとに順次行われ、各QPU上のジョブの一部がGen3パスを使用します。実験的オプションのgen3-turboを使用してGen3パスを強制することもできます。このエンジンスタックは、フラクショナルゲート、パルスゲート、動的回路とは互換性がないことに注意してください。

第4四半期

2024年10月15日​

  • backend.runのサポートが終了しました。

2024年10月1日​

  • パラメーター化された遅延ゲートは非推奨になりました。
第3四半期

2024年8月15日​

  • 確率的誤り増幅（PEA）エラー抑制法がEstimator V2で利用可能になりました。詳細については、ZneOptions APIリファレンスを参照してください。

  • 新しいヘルパープログラムnoise-learnerが利用可能になりました。これにより、Pauli-Lindbladノイズモデルに基づいて、対象の1つまたは複数の回路のゲートに影響を与えるノイズプロセスを特性評価できます。出力されたノイズモデルは、layer_noise_modelオプションを介してEstimatorに渡すことができます。

  • V1プリミティブはサポートされなくなりました。

2024年7月3日​

  • 以下のエンドポイントは非推奨であり、2024年10月3日以降に削除されます。GET /stream/jobsおよびGET /stream/jobs/{id}。この削除には以下の影響があります。

    • エンドポイントが削除された後、job.stream_results()およびjob.interim_results()はqiskit-ibm-runtimeクライアントから削除されます。

    • job.result()などの追加のメソッドは、現在非推奨のエンドポイントを使用しています。中断を避けるため、エンドポイントが削除される前にqiskit_ibm_runtime 0.25以降にアップグレードしてください。

第2四半期

2024年6月18日​

  • optimization_levelオプションはEstimator V2で非推奨となり、2024年9月30日以降に削除されます。

2024年6月3日​

  • 確率的誤り増幅（PEA）エラー抑制法が、Estimator V2の実験的オプションとして利用可能になりました。詳細については、EstimatorOptions APIリファレンスを参照してください。
第1四半期

2024年3月28日​

  • Qiskit Runtimeプリミティブは、回路の入力形式としてOpenQASM 3、および標準のJSON出力形式をサポートするようになりました。例については、Qiskit Runtime REST APIを参照してください。
