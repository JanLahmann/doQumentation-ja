誤り訂正 II：量子優位性にとって誤り訂正が適切な手段となるのはいつか？

前提知識

このレッスンは、誤り訂正 Iで導入したスタビライザーチェックの考え方を土台としています。パウリチェック、シンドローム、符号距離、そしてサーフェスコードのチェックが 2D レイアウト上で局所的であるという考え方に慣れていることを前提とします。スタビライザー符号の完全な形式的取り扱いは、IBM Quantum® Learning の John Watrous による量子誤り訂正の基礎コースで学べますが、本文で必要なのは、続くオプションの復習にまとめた実用的な考え方だけです。ここでは、形式論を導出するのではなく、使うレベルにとどめます。

スタビライザーが初めての方、または簡単に復習したい方は、この 5 分間の復習を開いてください。

この復習は任意であり、訂正とデコーディングに必要な最小限の記法のみを確認します。Part 1〜6 を追うには十分ですが、より詳細なセクションやセクション 3.1ではさらに多くの知識を前提とします。

  • パウリ演算子。 XXX は ∣0⟩↔∣1⟩|0\rangle \leftrightarrow |1\rangle∣0⟩↔∣1⟩ を反転させ（ビットフリップ）、ZZZ は ∣1⟩|1\rangle∣1⟩ の符号を反転させ（位相フリップ）、Y=iXZY = iXZY=iXZ です。

  • スタビライザー／チェック。 符号化された状態が変化させない（固有値 +1+1+1）複数量子ビットのパウリ演算子（例：Z1Z0Z_1 Z_0Z1​Z0​）です。これを測定することはパリティチェックにあたり、乱されていなければ +1+1+1 を、それと反可換なエラーが生じていれば −1-1−1 を返します。符号化されたデータ自体を測定することはありません。

  • シンドローム。 ±1\pm 1±1 のチェック結果の一覧です。エラーに関する部分的な情報（正確な位置ではなく、符号化された状態については何も）を持つ古典的なビット列です。デコーダーはここから最も可能性の高いエラーを推定します。

  • 重み。 エラー（複数量子ビットのパウリ演算子）が非自明に作用する量子ビットの数です。例えば、Z4X1Z_4X_1Z4​X1​ の重みは 2 です。

  • 符号距離 ddd。 すべてのチェックをすり抜けて論理エラーとなりうる最小のエラーの重みです。ddd が大きいほど保護も強くなります。

  • [[n,k,d]][[n, k, d]][[n,k,d]]。 nnn 個の物理量子ビットで、距離 ddd の kkk 個の論理量子ビットを保護します。例えば、[[7,1,3]][[7,1,3]][[7,1,3]] は 7 個の物理量子ビットで 1 個の論理量子ビットを距離 3 で保護します。

  • CSS 符号。 Calderbank-Shor-Steane（CSS）符号は、チェックが純粋な XXX 型と純粋な ZZZ 型に分かれ、それぞれ独立に扱われます。サーフェスコードと二変量自転車（BB）符号は CSS 符号です。

このレッスンで問うのは、量子誤り訂正（QEC）が何であるかではなく、どのような場合に量子優位性にとって適切な手段となるかです。これに答えるため、コストがどこから生じるか（Part 1 と 2）、どのように削減できるか（Part 3）、そしてどこで消えるのではなく移動するのか（Part 4 と 5）を追跡します。その後、これらすべてを優位性の判断にまとめます（Part 6）。

これまでのレッスンでは、量子計算の精度を保ついくつかの方法を紹介しました。物理的なエラーがどのように発生し蓄積するか、それらをどのように抑制または整形できる場合があるか、そして追加の実行と古典的な後処理によってその影響をどのように軽減できるかを見てきました。前のレッスンでは、さらに別の考え方として、破損した実行を特定して破棄できるよう、計算にチェックを組み込む方法を加えました。時空間チェックを含む、符号に基づくシンドロームのポストセレクションは、ポストセレクション型の量子誤り訂正の一形態です（Qiskit Paulice ブログ）。これにより保持されるデータの品質は向上しますが、制約も残ります。検出されないエラーがあること、チェックが作動しても何かが起きたことがわかるだけで最も可能性の高い障害は特定できないこと、そしてこの手法はオーバーヘッドの低いチェックを支える構造を持つ回路で最も効果的であることです。デコーディングに基づく訂正は、同じチェック情報を土台にしています。実行を保持するか破棄するかを問う代わりに、観測されたパターンと最も整合するエラーは何か、符号化された情報をどう回復すべきかを問います。ここでの違いは、シンドロームに基づくポストセレクションと、回復を伴うデコーディングの間にあり、これらは同じ QEC の連続体上にある 2 つのアプローチです（QEC continuum ブログ）。この追加の能力により、リソースのトレードオフが変わります。デコーディングに基づく訂正は、コストをより多く物理量子ビット、シンドローム抽出、デコーディング、接続性、アーキテクチャへと移します。これは QEC の連続体に沿って、サンプリングコストを追加の量子ビットやハードウェアリソースと引き換えにするものであり（QEC continuum ブログ）、より軽量な手法ではタスクが必要とする深さや信頼性を支えられない場合に中心的となります。

このレッスンでは、まずデコーディングと回復を前のレッスンのポストセレクション手法に結び付け、次に、保存された量子情報を保護する最も確立された方法と、それがなぜ非常にコストが高いのかを取り上げます。そこから、そのコストをどう削減できるかを問い、最近の具体的な提案をケーススタディとして検討します。続いて、保存された情報を保護するだけでは有用な計算には不十分である理由と、完全なアルゴリズムに必要な追加のリソースを説明します。次に、一歩引いて、デコーダー、モジュラーアーキテクチャ、そして他のハードウェアプラットフォームが引き継ぐさまざまな課題を含め、誤り訂正をシステム全体として捉えます。レッスンは、Lanes らの中心的な問い、すなわち誤り訂正はいつ量子優位性の維持に役立ち、いつそのオーバーヘッドが優位性を消し去るのか、という問いで締めくくります。

対象範囲について

量子誤り訂正はあらゆるハードウェアプラットフォームの課題ですが、その形は異なります。このレッスンでは、Lanes ら、2025の主要な枠組みを保ちつつ、二変量自転車符号とグロス符号アーキテクチャに関する IBM® の最近の成果を具体的なケーススタディとして使います。この範囲で、2D 超伝導トランズモン上のスタビライザー符号（トランズモンは超伝導量子ビットの最も一般的な種類）に焦点を当てます。そこでの設計課題は、平面のグリッド上にチェックを配置し、非局所的な接続をモジュラーハードウェアで吸収することです。イオントラップ、中性原子、ボゾンモード、トポロジカル量子ビットのプラットフォームは異なる課題を引き継ぎ、それらは Part 5 で再び取り上げます。それまでは、「物理量子ビット」「スタビライザーチェック」「2D レイアウト」は超伝導の設定を指すものとして読んでください。

Part 1：検出から、エラー回復のためのスタビライザー符号による訂正へ​

この Part では、検出と訂正の関係を具体的に示します。チェックに基づく考え方と符号距離の概念は前のレッスンですでになじみがあるため、簡単に振り返り、訂正が同じ情報をどのようにより十分に活用するかを見ていきます。これは、レッスンを通じて続くコスト会計の最初の項目です。訂正は検出より多くのものを得られる代わりに、その対価はまず必要な符号距離に現れます。重み www のエラー（www 個の量子ビットに非自明に作用するもの）を検出するには d≥w+1d \ge w+1d≥w+1 が必要ですが、訂正するには d≥2w+1d \ge 2w+1d≥2w+1 が必要です。

1.1 振り返りと、訂正で変わること​

このセクションで使うチェックに基づく考え方は新しいものではありません。誤り訂正 Iでは、[[4,2,2]][[4,2,2]][[4,2,2]] 検出符号を導入する際にすでにスタビライザーチェックとそのシンドロームを扱い、符号距離は、符号が検出できない最小のエラー重みとして登場しました。

訂正で変わるのは、これらの対象の使い方です。同じチェックが返すシンドロームは、何かが起きたことを確認するだけでなく、それ以上の役割を果たさなければなりません。デコーダーが可能性の高い回復を選べる程度まで、候補を絞り込む必要があります。同じ符号距離 ddd も、より強い役割を担います。距離 ddd の符号は、重みが ⌊(d−1)/2⌋\lfloor (d-1)/2 \rfloor⌊(d−1)/2⌋ までの任意のエラーを訂正できます。これは検出だけの場合のおよそ 2 倍の厳しさです（重み www のエラーの検出には d≥w+1d \ge w+1d≥w+1 が必要ですが、訂正には d≥2w+1d \ge 2w+1d≥2w+1 が必要です）。この 2 つの強化、つまり情報を持つシンドロームと距離のより厳格な使い方が、訂正を前のレッスンの検出ステップと区別し、後のセクションで検討するコストの土台となります。

1.2 具体例：3 量子ビット反復符号​

デコーディングとしての訂正の最も単純な例が、3 量子ビット反復符号です。ビットフリップに対してのみ保護される 1 つの論理量子ビットを 3 つの物理量子ビットに符号化すると、2 つのパリティチェック Z1Z0Z_1 Z_0Z1​Z0​ と Z2Z1Z_2 Z_1Z2​Z1​ から 1 回のビットフリップを推定できます。シンドロームは、何かが起きたことを知らせるだけではありません。どの量子ビットが反転した可能性が最も高いかを示すため、多数決によって論理値を回復できます。

符号化回路、スタビライザーの図式、シンドローム表、論理エラー曲線については、ここで完全に導出し直すのではなく、Watrous の量子誤り訂正の基礎コースを参照先とします。そのコースが強調しているように、反復符号は限定的な量子符号にすぎません。ビットフリップには対応しますが位相エラーには対応しないため、教育的な出発点としてのみ捉えるのが最適です。

この例から引き継ぐ考え方が 2 つあります。1 つ目は、シンドロームが情報を持ち、単なるフィルタリングではなくデコーディングを可能にすることです。これがセクション 1.1で述べた検出から訂正へのステップです。2 つ目は、論理エラー率が改善するのは、物理エラー率がしきい値のような交差点を下回る場合だけだということです。3 ビット反復符号では、デコード後のエラー率 3p2−2p33p^2 - 2p^33p2−2p3 が符号化しない場合のエラー率 ppp より低くなるのは、p<1/2p < 1/2p<1/2 のときだけです。この単純な図は、後のセクション、特に Part 2 のサーフェスコードで再び現れる、より重要なしきい値の振る舞いを予告しています。

3 量子ビット反復符号の符号化回路。出典：Watrous、量子誤り訂正の基礎、反復符号、IBM Quantum Learning。

# the 3-qubit repetition code

def syndrome(flip):
    qc = QuantumCircuit(5)  # q0,q1,q2 = data ; q3,q4 = syndrome ancillas

    if flip is not None:
        qc.x(flip)  # inject one bit-flip error
    qc.cx(0, 3)
    qc.cx(1, 3)  # ancilla q3 <- parity of (q0, q1) = Z1 Z0 check
    qc.cx(1, 4)
    qc.cx(2, 4)  # ancilla q4 <- parity of (q1, q2) = Z2 Z1 check
    sv = Statevector(qc)
    idx = int(np.argmax(np.abs(sv.data)))  # the state is a single basis ket
    bit = [(idx >> q) & 1 for q in range(5)]  # qiskit little-endian readout
    return (bit[3], bit[4])

# Build the syndrome table: each single-qubit-flip gives a DISTINCT syndrome.
table = {}
print("error    (Z1Z0, Z2Z1)")
for flip in [None, 0, 1, 2]:
    s = syndrome(flip)
    table[s] = flip
    print(f"  {('none' if flip is None else 'flip q'+str(flip)):8s} {s}")

# The decoder is just the inverse lookup: syndrome -> most-likely flip -> undo it.
def decode(s):
    return table[s]
error    (Z1Z0, Z2Z1)
  none     (0, 0)
  flip q0  (1, 0)
  flip q1  (1, 1)
  flip q2  (0, 1)

3 ビット反復符号の符号化後のエラー率は 3p2−2p33p^2 - 2p^33p2−2p3 です。3 つの量子ビットのうち少なくとも 2 つが反転すると多数決は失敗するため、失敗確率は (32)p2(1−p)+(33)p3=3p2−2p3\binom{3}{2}p^2(1-p) + \binom{3}{3}p^3 = 3p^2 - 2p^3(23​)p2(1−p)+(33​)p3=3p2−2p3 となります。これを符号化しない場合の率 ppp に対してプロットすると、p=1/2p = 1/2p=1/2 での交差点が明確になります。同じ視覚的な論理（符号化後のエラーが、交差点より下で符号化なしのエラーより低い）は、Part 2 のサーフェスコードでも再び現れ、そこでは交差点が符号のしきい値となり、関心のある物理エラー率はそれをはるかに下回ります。

このプロットは、訂正がいつそのコストに見合うかも説明しています。浅い回路では優位性は小さく、前のレッスンの軽量な手法（抑制、軽減、検出して破棄）で結果を意味のあるものに保つのに十分なことが多くあります。深さが増すと状況は変わります。回路の規模が大きくなると、厳密な軽減手法には急速に増大する（多くの場合は指数的な）サンプリングオーバーヘッドが必要になり、ポストセレクションによる検出では保持される実行の割合が縮小していきます。これは、Shor の素因数分解アルゴリズム、位相推定、およびそれに基づく深い化学ルーチンなど、深い汎用フォールトトレラントアルゴリズムに当てはまります。そこでは、物理量子ビット、デコーディング、接続性に大きなアーキテクチャ上のオーバーヘッドを支払う代わりに、深さに対して緩やかに増加するエラー率が得られるため、訂正が重要になります。Lanes ら、2025の枠組みでは、近い将来の優位性の主張は、深さと検証の要件が許す範囲で、なお軽減やポストセレクションによる検出に頼る場合があります。それらの手法では必要な深さで厳密なエラー制御ができない場合にデコーディングに基づく訂正が中心となり、軽減とポストセレクションはそれを補完し続けることができます。

理解度チェック​

シンドロームは量子状態ですか、それとも古典的なビット列ですか。また、何がわかりますか？

答え

シンドロームは古典的なビット列で、±1\pm 1±1 のチェック結果の一覧です。エラーに関する部分的な情報を持ち（符号化された論理状態については持たず、それを崩壊させることもありません）、デコーダーはそこから最も可能性の高いエラーを推定します。

Part 2：2 次元スタビライザー符号と、局所性・レート・距離のトレードオフ​

この Part では 2 つの選択がトレードオフの枠組みとなります。サーフェスコードは局所的なチェックを使うためハードウェア実装が簡単になりますが、規模とともにオーバーヘッドが増大します。量子低密度パリティ検査（qLDPC）符号は疎で非局所的なチェックを使い、オーバーヘッドを縮小できますが、ハードウェアとデコーダーが難しくなります。この Part の残りは、このトレードオフがなぜ存在するのかについてです。サーフェスコードは最も研究されている量子誤り訂正符号の一つであり、訂正のオーバーヘッドを論じる上で自然な出発点です。2 つの特徴により、超伝導の設定における基準ベースラインとなっています。スタビライザーチェックが 2 次元グリッド上の最近接どうしの間で作用し、主要なハードウェアの接続性と一致していること、そして比較的高いノイズしきい値を持ち、実際に現実的な物理エラー率で有用な論理エラー率に到達できることです。この Part では、そのコストを論じるのに必要なレベルでサーフェスコードを紹介し、次にそのコストが構造的にどこから来るのかを問い、最後に厳密な 2D 局所性の仮定を緩める、より広い符号の全体像を概観します。このコストが避けにくい理由は構造的なものです。チェックが 2D グリッド上の最近接どうしの間でのみ作用するどの符号でも、無次元の比 kd2/nkd^2/nkd2/n は定数で上限が決まり、これを Bravyi-Poulin-Terhal（BPT）の上限と呼びます。この上限が優位性を抑え込むことを、セクション 2.3で展開します。

2.1 2D 格子上のスタビライザー​

サーフェスコードは、スタビライザーチェックを 2 次元グリッドに組み上げます。データ量子ビットは正方格子の辺上にあり、補助量子ビットは面上と頂点にあります。各補助量子ビットは、隣接する 4 つのデータ量子ビットに対して、最近接の 2 量子ビットゲートのみを使って重み 4 のスタビライザー（頂点まわりの X 型または面まわりの Z 型）を測定します。シンドローム抽出回路全体が平面レイアウトに収まるため、サーフェスコードは平面の超伝導ハードウェアと整合します。

さらに 2 つの性質が、サーフェスコードを後の符号ファミリーに向けた基準としています。1 つ目はノイズのしきい値です。現実的な回路レベルのノイズの下では、物理エラー率がおよそ 1 パーセントを下回ると符号化が有効になります（Fowler ら、2012）。これは 1 パーセント程度のスケールとしてよく引用される水準であり、サーフェスコードが超伝導アーキテクチャの基準となった理由の一つです。2 つ目はデコーディングの成熟度です。標準的なパウリノイズの仮定の下では、シンドロームから最も可能性の高いエラーを推定する問題は、格子上のシンドロームの端点に対する最小重みマッチング問題として定式化されることが多く、効率的な古典アルゴリズムで解けます。

格子の幾何は、論理演算子の見た目も変えます。前のレッスンの [[4,2,2]][[4,2,2]][[4,2,2]] 符号では、論理演算子は距離に等しい重みの短いパウリ列でした。ここでは弦演算子であり、格子上の経路に沿った単一量子ビットのパウリの連鎖です。短いエラーの連鎖は 2 つの端点を持つ弦を作り、その端点のスタビライザーが作動します。連鎖そのものは直接観測されなくても、シンドロームは連鎖がどこで終わるかを明らかにします。デコーダーは端点だけを見て、それらを結ぶ最短の連鎖（黄色）をとりますが、これは必ずしも実際のものではありません。それで問題ありません。実際のエラーと訂正を合わせると閉じたループになり、点に縮められるループはスタビライザーの積であるため、推測した経路が「間違い」でも量子ビットは回復されます。これに対して論理エラーは、端点を持たない弦です。トーリックコードではトーラスを一周し、ここで注目する開境界のサーフェスコードでは、パッチの一方の境界から反対側の境界まで伸びます。距離 ddd は、そのような自明でない弦の最短の長さであり、距離 ddd のパッチの物理量子ビット数は d2d^2d2 に比例してスケールします。

2.3 局所性、レート、距離：Bravyi-Poulin-Terhal限界​

コードを比較する有用な方法は、ある数の物理量子ビットにいくつの論理量子ビットを詰め込めるかを見ることです。これがレートで、k/nk/nk/nと書きます。ここでkkkは符号化される論理量子ビットの数、nnnは使用される物理量子ビットの数です。サーフェスコードのレートはk/n=1/d2k/n = 1/d^2k/n=1/d2です。各論理量子ビットはそれぞれ独自のd×dd \times dd×dパッチを占有し、距離が大きくなるにつれてレートは消えていきます。

このレートの消失は、サーフェスコードに固有のものではなく、幾何学的な性質によるものです。Bravyi、Poulin、Terhalによる結果（Bravyi et al., 2010）、すなわちBPT限界は、2次元グリッド上で最近接の量子ビット間にのみチェックが作用するスタビライザーコードでは、積k d2k\,d^2kd2が定数倍を除いて物理量子ビット数を超えられないことを述べています。同じことですが、このファミリーのすべてのコードについて、無次元の比k d2/nk\,d^2/nkd2/nは定数で頭打ちになります。サーフェスコードの各種の形（回転型、平面型、トーラス型）はいずれも同じO(1)O(1)O(1)の値の近くにあり、正確な定数は境界の扱い方によって決まります。

その帰結は厳しいトレードオフです。厳密な2次元局所性の範囲内では、論理エラー率を抑えるために距離を大きくするとレートが小さくなり、論理量子ビット1個あたりの物理量子ビット数は距離とともに二次関数的に増加します。厳密な2次元局所性の範囲内では、積k d2k\,d^2kd2がO(n)O(n)O(n)で頭打ちになるため（BPT限界）、レートと距離の両方を大きくすることはできません。2次元局所のファミリーから外れたコードは、1桁以上うまくやれる可能性があります。下の表で、nnnはコードのパラメータ[[n,k,d]][[n,k,d]][[n,k,d]]で使われるコードのブロック長です。シンドロームのアンシラ、ルーティング、カプラー、測定ハードウェアは含まれていないため、ハードウェア全体のフットプリントではありません。

2.4 qLDPCの全体像​

量子LDPC（qLDPC）コードとは、パリティ検査行列がスパースであるスタビライザーコードのことです。パリティ検査行列は、行がスタビライザーのチェック、列が量子ビットに対応し（チェック1つにつき1行、量子ビット1つにつき1列）、チェックが量子ビットに作用する箇所に1を置いた二値の配列です。スパースとは、コードのサイズにかかわらず、各行と各列に含まれる1の数が小さく、有界であることを意味し、これが「低密度」の意味するところです。この定義により、サーフェスコード自体もqLDPCコードです。そのウェイト4のスタビライザーはnnnとともに増えないからです。近年注目されているqLDPCコードの特徴は、サーフェスコードよりスパースであることではなく、スパース性を保ったまま2次元局所性を緩和している点にあります。この緩和によって、2.3節で見たBPTの上限から逃れることができます。

「LDPC」という用語は古典的な符号理論に由来し、そこでは低密度パリティ検査符号が、良好なレートと効率的なデコードを両立することが古くから知られています。量子版は、スパースなチェックという構造上の利点を受け継ぎつつ、幾何学的な局所性の仮定を取り除いたものです。これを実現するファミリーがいくつかあります。ハイパーグラフ積コード（Tillich and Zémor, 2009）、リフテッド積コード（Panteleev and Kalachev, 2022）、量子Tannerコード（Leverrier and Zémor, 2022）、バイバリエイト・バイサイクルコード（Bravyi et al., 2024）などです。これらの一部は漸近的に良いコードで、コードが大きくなっても一定のレートと線形の距離を保ちます。これはサーフェスコードには達成できない性質です。

このレッスンで具体的なケーススタディとして取り上げるのは、第3部で詳しく調べるバイバリエイト・バイサイクルのファミリーです。これを選ぶ理由は、バイバリエイト・バイサイクルが最も強力なqLDPCのファミリーだという数学的な主張ではありません。アーキテクチャ上の整合性によるものです。公表されているIBMの超伝導ロードマップがこれらのコードを選んでいるのは、そのシックネス2のチェックグラフが、第5部で論じるモジュール式アーキテクチャの中で、提案されている超伝導ハードウェアに適合するからです。この範囲において、主な結果は次のとおりです。報告された回路レベルのメモリシミュレーションでは、バイバリエイト・バイサイクルコードは、p=10−3p = 10^{-3}p=10−3において、論理量子ビット1個あたりの物理量子ビット数をおよそ1桁減らしながら、サーフェスコードと同等のエラー抑制を達成できます（Bravyi et al., 2024、IBMのフォールトトレランス・ロードマップも参照）。コストはなくなりません。物理量子ビット数から、接続性（チェックグラフが2つの平面部分グラフに分かれ、長距離のエッジを含む）、デコード（最小重みマッチングが適用できなくなり、qLDPCのデコードは活発な研究分野です）、アーキテクチャ（その両方を支えるモジュール式ハードウェア）へと移ります。第3部では、このqLDPCの考え方を、BB/グロスコードの具体的なケーススタディにします。

答え

第3部：qLDPCのケーススタディとしてのBB/グロスコード​

第2部では、バイバリエイト・バイサイクルコードをqLDPCの全体像の中に位置づけ、報告されたメモリタスクのシミュレーションにおいて、選ばれたqLDPCコードがはるかに低い物理量子ビットのオーバーヘッドでサーフェスコードのメモリ目標に匹敵しうる理由を示しました。この部では、BBファミリーを腰を据えたケーススタディとして取り上げます。まず、構成が実際にどのようにコードを生み出すかをたどり（3.1節）、次にグロスコードをIBMのロードマップに載せることになったメモリ性能（3.2）、ファミリーが距離とともにどうスケールするか（3.3）、BBコード上での計算がメモリに加えて何をもたらすか（3.4）、そしてこのケーススタディが全体として何を示し、何を示さないか（3.5）を検討します。デコードとモジュール式ハードウェアは、より広いシステムの視点の一部として第5部に再び登場し、ユニバーサルゲートの仕組みは第4部で扱います。非局所なチェックを許すことは、BPT限界に違反することなく、その2次元局所の仮定の外へ踏み出すことです。この部で扱うメモリのタスクでは、その見返りとして、物理量子ビット数をおよそ1桁減らしながらサーフェスコードと同等のエラー抑制が得られます。

3.1 バイバリエイト・バイサイクル構成​

バイバリエイト・バイサイクル（BB）構成は、2つの短い多項式AAAとBBBから、スタビライザーコード全体を生成します。サーフェスコードが2次元グリッド上に局所的なプラケットを描いて構成されるのに対し、BBはパリティ検査行列を代数的に生成します。多項式の組(A,B)(A, B)(A,B)から、1つの規則で、グロスコードの72個のX-チェックと72個のZ-チェックがすべて得られます。この構成自体によって、得られるXチェックとZチェックが可換であること（言い換えれば、結果が正当なCSSコードであること）が保証されるため、手作業で課すべき可換条件はありません。与えられた(A,B)(A,B)(A,B)が有用なレート、距離、デコード特性をもたらすかどうかは、その後に数値的に調べられるため、設計は幾何学的な構成ではなく多項式の探索にできます。

グロスコードでは、多項式はA=x3+y+y2A = x^3 + y + y^2A=x3+y+y2とB=y3+x+x2B = y^3 + x + x^2B=y3+x+x2で、144個のデータ量子ビットを持つ12×612 \times 612×6のトーラス格子上で定義されます。ここでxxxとyyyは格子の2つの巡回シフト演算子（トーラスの各方向に「1ステップ動く」）であり、数ではありません。したがってx3x^3x3のような項は「3ステップずらす」ことを意味します（詳細は後述）。144個のデータ量子ビットは、それぞれ72個の量子ビットを含む2つのレジスタq(L)q(L)q(L)とq(R)q(R)q(R)に分かれます。ウェイト6の各チェックは、各レジスタの3つの量子ビットに作用します。バイプレーナーあるいはシックネス2という性質は、Tannerグラフが辺を共有しない2つの平面部分グラフに分かれ、カプラーを2つの層に配線できることを意味します。2つのデータレジスタを別々の物理平面に置くという意味ではありません（Bravyi et al., 2024）。下の図は、得られたチェック行列を、同じ格子上のサーフェスコードに似たコードと並べて描いたもので、同じ枠組みの中で多項式の選び方を変えると、パリティ検査のパターンが大きく異なることを示しています。この図は各チェックがどのデータ量子ビットに作用するかを示すもので、ハードウェア配置の図ではありません。

2つの行列は同じ72×14472 \times 14472×144のグリッドの中にありますが、パターンは大きく異なります。トーラスコードのウェイト4の行は、密な対角線の縞に詰まっています。各チェックは隣接する4つのデータ量子ビットにしか接続しません。グロスコードのウェイト6の行は、x3x^3x3とy3y^3y3の項がトーラスを3ステップ先まで届くため、より広い間隔でより多くの対角線に広がっています。多項式の選択がそのままコードであり、このレベルでは、2次元局所のコードと非局所なqLDPCコードの違いは、単にAAAとBBBの選び方の違いです。

この構成には3つの性質があります。

  • 常に正当なCSSコードを生成します。XチェックとZチェックは代数的に可換であり、上のセルで直接確認したとおりです。

  • ブロック長nnnと論理量子ビット数kkkは、多項式の組に対するF2\mathbb{F}_2F2​上のランク計算から求まります（k=n−rank HX−rank HZk = n - \mathrm{rank}\,H_X - \mathrm{rank}\,H_Zk=n−rankHX​−rankHZ​）。グロスコードのパラメータ[[144,12,12]][[144,12,12]][[144,12,12]]はBravyi et al., 2024から取ったものです。特に距離は、一般のqLDPCコードの距離を求めるのが難しいため、再計算せずに引用しています。

  • スパースだが非局所なチェックでも、エラーを効果的に検出できます。

こうした非局所なチェックのコストは、デコードの段階で再び現れます。チェックが非局所であるため、デコーダーが扱うシンドロームグラフは、もはやサーフェスコードの平面的なマッチンググラフではなく、最小重みマッチングを直接適用することはできません。このデコード問題の構造と、そのために開発された手法については、5.2節で扱います。

3.3 ケーススタディのスケーリング:two-gross​

gross符号はBBファミリーの中の一つの例であり、唯一の到達点ではありません。次に自然に浮かぶ疑問は、同じ構成を、より広いアーキテクチャを変えずに、より高い距離へ拡張できるのか、またその拡張にどれだけの量子ビット・コストがかかるのか、ということです。論文の答えはtwo-gross符号 [[288,12,18]][[288,12,18]][[288,12,18]] です。これは、同じ二変数自転車(bivariate-bicycle)の枠組みの中で、より大きな格子上の関連する多項式を選ぶことで得られます。この符号は同じ12個の論理量子ビットを保ったまま、距離を12から18に引き上げ、データ量子ビット数を144から288へと2倍にします(シンドローム補助量子ビットを含めると、物理量子ビットの総数は288から576に増えます)。

セクション2.3のBPT比の値を考えてみましょう。grossは k d2/n=12k\,d^2 / n = 12kd2/n=12 であり、two-grossは 12⋅182/288=13.512 \cdot 18^2 / 288 = 13.512⋅182/288=13.5 です。これらの比は、厳密な2次元局所性を緩めることの利点を示しています。BPT限界は、これらの非局所的なチェックには適用されません。grossとtwo-grossは、有限距離における2つの動作点です。前者はより少ない量子ビットを使い、後者は2倍のデータ量子ビット予算を費やして、より高い距離に到達します。grossからtwo-grossへ進むと、必要な量子ビット数と接続性の要件が増加します。IBMのモジュール式アーキテクチャ(セクション5.3)は、システムの拡大に合わせて、メモリ、処理、その他のモジュールを接続するように設計されています。

このスケーリングのステップは、BBファミリーが、独立した符号ブロックを複製することによってではなく(表面符号のメモリが複数の論理量子ビットへ拡大するときはそうなります)、より大きな格子上で多項式の選び方を変えることによって拡張されることを示しています。同じ代数的枠組み、同じシンドローム抽出回路の形、同じデコード問題のクラスが、ファミリー全体に適用されます。これらの有限サイズの例は漸近的な良さを示すものではありません。漸近的な良さには、ゼロでない極限レートと、符号長に比例して線形に増大する距離が必要です。このケーススタディのポイントは、近い将来のフォールトトレランスのロードマップに関連する有限距離の領域において、BBファミリーが、デコーダーや接続性の要件とあわせてコストを評価できる具体的な動作点を提供するということです。

3.4 メモリを超えて計算が加えるもの​

セクション3.2のメモリの結果は、符号化された論理状態を保護しますが、それらに対する演算は行いません。有用な計算には、論理ゲート(少なくとも、Clifford演算と非Clifford演算からなるユニバーサル・セット)と、それらを符号ブロック間で適用する方法が必要です。BBファミリーには、ここでさらに構造上の課題があります。チェックがチップ全体に非局所的に広がっているため、単一のBBブロック内の単純な演算でさえ、符号の性質を保つために注意が必要です。また、BBブロック間の演算には、メモリの構成には含まれないアーキテクチャ上の要素(カプラー、アダプター、マジック状態ファクトリー)が必要になります。

ケーススタディとして、ここでTour de gross(Yoder et al., 2025)を見ていきます。この論文はバイシクル・アーキテクチャを導入しています。これは、独立して製造されるモジュールから構成されるフォールトトレラントなシステムです。各符号モジュールは、メモリ符号ブロックと、一般化された格子手術によって論理演算を実装する、付随する論理処理ユニット(LPU)から成ります。別個のマジック状態ファクトリー・モジュールが非Clifford資源を供給し、ユニバーサル・アダプターがモジュール間の論理演算を実装します。同論文は、このアーキテクチャを6つの設計基準に照らして評価しています。フォールトトレラント(想定するアルゴリズムが成功するのに十分なほど論理エラーが抑制されること)、アドレス指定可能(計算中に個々の論理量子ビットを準備または測定できること)、ユニバーサル(論理ゲートの完全なセット、すなわちCliffordに加えて非Cliffordゲートが利用できること)、適応的、モジュール式(独立して製造される交換可能なモジュールから構築されること)、効率的(論理演算あたりの物理量子ビットと時間のオーバーヘッドが小さいこと)です。論文の用語では、適応的とは、シンドローム測定がリアルタイムにデコードされ、その後の量子命令を変更できることを意味し、これは真のリアルタイム・フィードフォワードです。(このレッスン全体では、代わりに補正をオフラインのフレーム更新として扱います。これは、コード・セルを短く正確に保つための、シミュレーションと教育上の意図的な便宜です。実際のフォールトトレラント計算には、前述の適応的なリアルタイム・フィードフォワード機能が必要です。TTT 注入後の SSS 補正と、パート4の格子手術の副産物は、後のゲートが先の測定結果に依存する箇所であるため、すべてをオフラインに先送りすることはできません。)論文は、表面符号アーキテクチャの場合よりも、与えられた物理量子ビット予算で桁違いに大きな論理回路を実行できることを示唆する、エンドツーエンドの資源見積もりを報告しています。

バイシクル・アーキテクチャ:二変数自転車符号に基づく、フォールトトレラントなモジュール式システム。各符号モジュールは、メモリ符号ブロックと、一般化された格子手術による論理演算のための論理処理ユニット(LPU)を組み合わせています。別個のマジック状態ファクトリー・モジュールが非Clifford資源を供給し、ユニバーサル・アダプターがモジュール同士を接続します。出典:フォールトトレランスのロードマップ。アーキテクチャの詳細はYoder et al., 2025を参照。 重要な問いは、セクション3.2のメモリレベルの優位性が、論理ゲート、マジック状態資源、モジュール間ルーティング、デコード、ハードウェア・レイアウトを含む計算の追加オーバーヘッドの後も保たれるかどうかです。Yoder et al. 2025のケーススタディの主張は、BBベースのアーキテクチャは、これらのオーバーヘッドを含めた後でも表面符号ベースのアーキテクチャと競争力を保て、メモリの優位性の一部を維持できる、というものです。アルゴリズム全体のレベルでの正確な差は、いまだ活発な資源見積もりの課題であり、裏付けとなる根拠は実験的な実証ではなく、アーキテクチャ解析です。このレッスンのパート4では、Clifford構造、非Clifford資源、マジック状態蒸留を含む、フォールトトレラント計算のユニバーサル・ゲート側を扱います。また、Xu et al., 2026の単一ブロック蒸留の提案も取り上げます。これは、マジック状態ファクトリーを単一のBB符号ブロックの内部で実行するものです。この提案は、別個の符号ブロックを割り当てる代わりに、量子ビットの再利用(同じ物理量子ビットを連続する蒸留ステップに転用すること)によって、ブロック自身の論理容量を再利用します。

3.5 この研究が示すことと、証明しないこと​

セクション3.1から3.4まででは、BBの構成(3.1)、IBMのロードマップにgross符号を位置づけたメモリ・ベンチマーク(3.2)、より高い距離へのファミリーのスケーリング挙動(3.3)、そしてメモリを超えて計算が加えるアーキテクチャ上の要素(3.4)を順に見てきました。このケーススタディが全体として示すのは、複数の論文にまたがる一貫した道筋です。すなわち、完全に規定されたqLDPC符号ファミリー、現実的な回路レベルのノイズの下で公表されたメモリの評価、同じ構成の中でより高い距離へ進むスケーリング・ステップの実証、そして符号化された量子ビット上でのユニバーサル計算に取り組むシステムレベルのアーキテクチャの提案です。

この研究が証明しないこと:

  • 最適性。 二変数自転車符号は、特定のアルゴリズムやプラットフォームにとって、必ずしも最適なqLDPCの選択ではありません。ハイパーグラフ積符号、リフテッド積符号、量子Tanner符号が存在し、それぞれに独自の漸近的および有限サイズでの利点があります。IBMのロードマップでのBBの選択はアーキテクチャ上の整合性によるものです。これは、厚さ2のチェック・グラフが、提案されている超伝導ハードウェアとモジュール式アーキテクチャに適しているためです。数学的な最適性の主張ではありません。

  • アルゴリズムの資源数。 Bravyi et al.が報告する、およそ桁違いのメモリ削減は、特定のノイズモデルと目標に対するものです。実際のアルゴリズムには、メモリの評価では捉えられない追加の資源要件(ゲート、マジック状態蒸留、ルーティング、リアルタイム・デコーダーのレイテンシー)があります。最も正直な要約は、メモリのタスクでは桁違いの削減、計算とシステムレベルのオーバーヘッドはまだ明らかにされつつある段階というものです。

  • ハードウェアの存在。 完全なスケールでgross符号が必要とする接続性は、本稿執筆時点では構築されていません。IBMのチップのロードマップ(セクション5.3の系譜の表)が、それを構築するための提案された道筋です。このスケジュールが守られるかどうかは、公表された符号理論の結果ではなく、エンジニアリングの実行力の問題です。

二変数自転車のケーススタディは、最近のQECの革新が、特定のプラットフォームに向けて、フルスタック(符号、回路、アーキテクチャ、デコーダー、統合計画)をどのように通して進められるかを示す一例です。パート4では、ユニバーサルなフォールトトレラント計算の問題そのものに目を向け、Clifford構造と非Clifford構造をより深く掘り下げます。パート5では、デコーダー、モジュール式ハードウェア、その他のプラットフォームにまたがる量子・古典システムとしてのQECに戻ります。そこでは、Relay-BPデコーダー(Müller et al., 2025)とIBMのモジュール式チップのロードマップが、この符号レベルの話のシステムレベルの対応物として再び登場します。

パート4:ユニバーサルなフォールトトレラント計算​

パート3では、二変数自転車のケーススタディがメモリを安価にすること、そしてバイシクル・アーキテクチャがシステムレベルで計算に取り組むことを示しました。このパートでは、BB固有の話から一歩引いて、あらゆるフォールトトレラント計算に必要なユニバーサル・ゲートの基本要素、すなわちClifford演算、非Cliffordゲート、蒸留を見ていきます。説明は、BB符号に戻ってケーススタディ固有の貢献を一つ扱うセクション4.4まで、プラットフォームに依存しません。メモリはコスト台帳の一行にすぎません。計算はコストを非Clifford資源へ移し、それを合算して初めて実質的な割引が見えてきます。台帳の利点はシステム全体にあり、メモリの一行だけにあるのではありません。

4.1 Clifford構造と非Clifford資源の必要性​

Clifford群 C\mathcal{C}C は、共役によってPauli演算子をPauli演算子に写すユニタリの集合です。標準的な生成元は、アダマール・ゲート HHH、位相ゲート S=diag(1,i)S = \mathrm{diag}(1, i)S=diag(1,i)、2量子ビットの CNOT\mathrm{CNOT}CNOT です。Clifford演算はPauli構造を保つため、符号化、論理Cliffordゲート、スタビライザー測定はすべてこの枠組みの中で記述できます。表面符号では、論理Cliffordは格子手術(パッチの切断と結合)と、選ばれた*横断的(トランスバーサル)*ゲートによって実装されます。横断的ゲートは、ブロック内のどの2つの量子ビットも相互作用することなく、量子ビットごとに独立して適用されるため、単一の物理的な故障がブロック内で高ウェイトのエラーに成長することはありません。これが、そうしたゲートが自動的にフォールトトレラントになる理由です。BB符号については、セクション3.4のバイシクル・アーキテクチャが、論理処理ユニット内で一般化された格子手術を使用し、その根底には同じCliffordに適した構造があります。

Clifford群だけでは、量子計算にとってユニバーサルではありません。Gottesman-Knillの定理がこの限界を正確に述べています。計算基底での状態準備、Cliffordゲート、計算基底での測定のみを用いる量子回路は、古典的に効率よくシミュレートできます(Gottesman, 1998)。したがって、ユニバーサル計算には少なくとも一つの非Cliffordゲートが必要です。標準的な選択は T=diag(1,eiπ/4)T = \mathrm{diag}(1, e^{i\pi/4})T=diag(1,eiπ/4) ゲート(π/8\pi/8π/8 ゲート)で、これはClifford群とともに SU(2n)\mathrm{SU}(2^n)SU(2n) の稠密な部分群を生成します。TTT をフォールトトレラントに実装することが、ユニバーサルなフォールトトレラント計算における難所であり、このパートの残りでその方法を見ていきます。

4.2 マジック状態注入による TTT ゲート​

表面符号は、横断的な論理 TTT をサポートしません。ここで議論している表面符号とBBのアーキテクチャは、マジック状態注入によってそれを実装します。方法は、事前に準備しておいた論理 ∣A⟩=T∣+⟩=(∣0⟩+eiπ/4∣1⟩)/2|A\rangle = T|+\rangle = (|0\rangle + e^{i\pi/4}|1\rangle)/\sqrt{2}∣A⟩=T∣+⟩=(∣0⟩+eiπ/4∣1⟩)/2​ というマジック状態を消費し、データ量子ビットに事実上 TTT を適用するClifford演算のみの回路を実行することです。回路は以下に静的な図として示します。このレッスンでは、補助量子ビットの測定に続く条件付きClifford補正を、能動的な回路途中の補正ではなく、Cliffordフレームの更新として扱います。

ここで使われる標準的なレシピ(フォールトトレラントなCliffordゲートと、注入によって供給される TTT)は、2つの構造的な結果に動機づけられています。

Gottesman-Knillの定理により、計算基底での準備と測定を伴うレベル2のゲートのみを使う回路は、古典コンピューター上で効率よくシミュレートできます。したがって、ユニバーサルな量子計算には少なくとも一つの非Clifford資源が必要です。TTT ゲートは、そのようなゲートの中で最も単純であり、{C,T}\{\mathcal{C}, T\}{C,T} が SU(2n)\mathrm{SU}(2^n)SU(2n) で稠密であることから、標準的な選択です。ただし、理論上、Toffoliやより高いレベルの演算ではなく TTT を選ばなければならない理由はありません。

Eastin-Knillの定理。 2つ目の結果は、より制約的です。Eastin-Knillの定理は、任意の単一量子ビットのエラーを検出する符号は、横断的な論理ゲートのユニバーサル・セットを持てないことを述べています(Eastin and Knill, 2009)。どのゲートが横断的かは符号に依存します。ここで議論している表面符号とBBのアーキテクチャは、論理 TTT にマジック状態注入を使います。横断的なセットは、必ずしもClifford群であるとは限りません。たとえば、セクション4.3で蒸留に使われる [[15,1,3]][[15,1,3]][[15,1,3]] Reed-Muller符号は、代わりに横断的な TTT を持ちます。Eastin-Knillのポイントは、固定された符号に対するユニバーサルな横断的セットの制限です。ユニバーサル性のためには、マジック状態注入のような追加のフォールトトレラントな仕組みが必要です。

注入がこれを解決する理由。 注入は、Clifford演算、測定、そして供給された論理マジック状態 ∣A⟩|A\rangle∣A⟩ を使って論理 TTT を実装します。そのマジック状態の準備には、非Clifford資源が必要です。状態の準備は、消費の時点から切り離してオフラインで行えます。セクション4.3の蒸留が、そのオフラインでの準備を論理レベルの忠実度まで引き上げます。

同様の注入の手法は、他の非Cliffordゲートにも適用できます。多くのフォールトトレラントな資源見積もりでは、何らかのマジック状態を使います。通常は、TTT には ∣A⟩|A\rangle∣A⟩、Toffoliには ∣CCZ⟩|\mathrm{CCZ}\rangle∣CCZ⟩、あるいはより高次の状態です。このレッスン全体で TTT を選ぶのは、基準となる慣例です。

「論理 TTT を実行する」という変換は、「高忠実度の論理マジック状態 ∣A⟩|A\rangle∣A⟩ を供給する」という変換になりました。これは資源供給の問題です。このパートの残りでは、その供給に取り組みます。

4.3 マジック状態蒸留​

そもそもなぜ別個の純化ステップが必要なのかを、一度立ち止まって考える価値があります。フォールトトレラントなコンピューターが安価に行えること(Cliffordゲートとスタビライザー測定)はすべて、符号によって直接保護されます。欠けている要素は、非Cliffordの TTT ゲートです。マジック状態注入は、あらかじめ作られた ∣A⟩|A\rangle∣A⟩ 状態をClifford演算のみの回路で消費することでこれを回避しますが、困難が移動しただけです。注入された生のマジック状態は物理レベルのエラーを引き継ぐため、深い論理回路にはノイズが多すぎます。忠実度 1−10−21 - 10^{-2}1−10−2 の生の ∣A⟩|A\rangle∣A⟩ を通じて適用された TTT ゲートは、論理エラー 10−1210^{-12}10−12 を目指す論理回路には役に立ちません。

蒸留は、その標準的な解決策です。多数のノイズを含むマジック状態を入力として受け取り、より少数の高忠実度の状態を出力として生成します。使うのはClifford演算と測定のみで、これは基礎となる符号がネイティブにサポートしています。最もよく研究されているプロトコルは15-to-1蒸留(Bravyi and Kitaev, 2005)です。エラー確率 ppp の15個のノイズを含むマジック状態から、[[15,1,3]][[15,1,3]][[15,1,3]] Reed-Muller符号を使って、∼35 p3\sim 35\,p^3∼35p3 の出力が1つ得られます。(353535 は、検出されない先頭のウェイト3のエラーパターンの数を数えたものです。) 3乗の抑制 p→35 p3p \to 35\,p^3p→35p3 は、ラウンドを重ねて反復されます。生のエラー p=10−2p = 10^{-2}p=10−2 から始めると、1ラウンドで ∼3.5×10−5\sim 3.5 \times 10^{-5}∼3.5×10−5、2ラウンドで ∼1.5×10−12\sim 1.5 \times 10^{-12}∼1.5×10−12 になります。各ラウンドで生の状態のコストが15倍になるため、深いエラー目標に到達するには、必要な入力状態の数の面で高コストになります。

def distill_rounds(p_in, rounds):

        p = 35 * p**3
        raw *= 15
        rows.append({"round": r, "error_estimate": p, "raw_states_per_output": raw})
    return pd.DataFrame(rows)

4.5 このパートが確立することと、証明しないこと​

5.1 QECの古典的な半分としてのデコーダー​

デコーダーは、古典的な推論問題を解きます。ノイズを含むシンドロームの履歴が与えられたとき、保護された論理状態を知ることなく、可能性の高い回復クラスを推論します。

スタビライザー符号のチェックを測定すると、どのチェックが反応したかを示す、シンドロームと呼ばれる古典的なビット列が得られます。デコーダーの役割は、このシンドロームを受け取り、どのエラーが最も起こりやすかったかを推論することです。これにより、推論されたエラーを論理的な解釈の中で考慮に入れることができます。通常は、ノートブック内でエラーを物理的に元に戻すのではなく、古典的なPauli/Cliffordフレームを更新することで行います。したがってデコーダーは古典的です。フィールド・プログラマブル・ゲート・アレイ(FPGA)、特定用途向け集積回路(ASIC)、GPU、CPUといった従来のハードウェア上で動作し、それなしではスタビライザー符号がいかなる情報も保護できない、量子・古典ループの一部です。

最も単純なデコーダーはルックアップ・テーブルで、シンドローム(ビット列)から最も可能性の高いエラー(Pauli列)への関数です。チェックが非常に少ない符号では、これは自明ですが、ルックアップ・テーブルの方式はスケールしません。次のセルで示すように、エントリー数はチェック数 mmm に対して 2m2^{m}2m で増加します。

5.2 符号ファミリーごとのデコーダーファミリー​

サーフェス符号は主に最小重み完全マッチング(MWPM)でデコードされます。シンドロームの欠陥はエラー列の端点に対として現れ、最小重みのペアリングによって最も可能性の高いエラーが推論されます。MWPMは多項式時間で実行でき(最小重みマッチングのブロッサム・アルゴリズム)、リアルタイムのレイテンシーを達成するFPGA実装として設計されており、フォールトトレラントなプロトタイプにとって成熟した基準ベースラインです。

標準的な最小重みマッチングは、二変数自転車符号には直接適用できません。1つのPauliエラーが2つより多いシンドロームビットを引き起こす場合があり、最も可能性の高いエラーの問題はもはや単純なマッチングではないためです。標準的なqLDPCデコーダーは、順序統計デコーディングを伴う信念伝播(BP + OSD)です。BPは符号のTannerグラフ(すべての量子ビットとすべてのチェックにノードがあり、チェックが量子ビットに作用する箇所に辺を持つ二部グラフ)上でメッセージを渡してエラーを推論し、OSDはBPが収束しない場合を整理します。BP + OSDは正確ですが、リアルタイムのループには遅すぎる場合があります。

Relay-BP(Müller et al., 2025)は、このレイテンシーに対処するためにBPの収束を高速化する、IBMによる最近の提案です。超伝導のQECサイクルでは約1 µsごとに新しいシンドロームが生成されるため、速度が重要です。デコーダーが平均して追いつけないと、未処理のシンドロームが積み上がり(バックログ問題)、論理エラーが増大します。より優れた符号だけでは、遅れをとるデコーダーを救えません。したがって、決定的な要件は精度だけでなく、平均デコード時間をサイクルあたりの予算内に収めることであり、デコーダーのレイテンシーはシステム要件です。その後、FPGAプロトタイプによってサイクルあたりのデコードレイテンシーがこの予算内に収まりました(Maurer et al., 2025)。

第6部: 量子優位性の枠組みにおける量子エラー訂正​

Lanes et al., 2025は、優位性を2つの基準に基づいて定義しています。結果は厳密に検証されなければならず、古典的手法に対する真の量子的分離を示さなければなりません。実際の運用では、精度スペクトルによって、これらをあらゆる主張に対する4つの具体的な問いに変換できます。

  1. タスクは何か? サンプリング問題、期待値計算、探索、構造化シミュレーション、アナログ問題では、それぞれ正しさの基準が異なります。

  2. 正しさはどのように検証されるか? 正しさは厳密に検証されなければならず、性能は利用可能な最良の古典的手法と比較して評価されます。検証には、古典的な検証、手法間のクロスチェック、あるいはサンプリングにおけるピーク性などの構造的性質を使用できます。

  3. どのリソースを支払うか? サンプル、量子ビット、デコード計算、ランタイム、接続性、キャリブレーション時間、または古典的な後処理です。スペクトル上の各ツールは、それぞれ異なるリソースを支払います。

  4. QECは、オーバーヘッドの後も量子的分離を維持するか、それとも失わせるか? QECが意図どおりに機能する場合でも、それが加えるオーバーヘッドによって、量子アルゴリズムと古典アルゴリズムの分離が、アルゴリズム的な高速化で得られる分より小さくなることがあります。厳しい論理エラー目標の深い回路では、QECがスケーラブルなエラー制御の標準的な方法です。浅い回路や近い将来の優位性の期間では、抑制と緩和の組み合わせ、あるいは事後選択による検出のほうが、実効的な分離が良好になる場合があります。

これらのツールは直線的なレシピではなく、リソースのメニューを形成します。実際のワークロードはメニューの一部を選び、検証と分離の分析によって、その選択が優位性への隔たりを埋めるかどうかが分かります。

コストの交差点​

精度スペクトルの各ツールのコストの形は、質的に異なります。これまでのレッスンで重点的に扱った手法では、緩和と事後選択による検出のコストが、回路ボリュームまたは総エラー率に対して指数関数的に増加することがあります。確率的エラーキャンセル(PEC)のサンプリング・オーバーヘッドはおおよそ exp⁡(c⋅V⋅p)\exp(c \cdot V \cdot p)exp(c⋅V⋅p) で増加し、事後選択による検出の受理率はおおよそ exp⁡(−c′⋅V⋅p)\exp(-c' \cdot V \cdot p)exp(−c′⋅V⋅p) で減衰します。ここで VVV は回路ボリューム、ppp は物理エラー率です。この模式的なモデルはほぼ独立な障害を仮定しており、定数はプロトコルとチェックの網羅範囲に依存します。デコーディングを伴うフォールトトレラントな訂正は、異なる形を持ちます。最初に大きなアーキテクチャ上のオーバーヘッド(符号パッチ、マジック状態ファクトリー、デコーダー、モジュラー・ハードウェア)を支払い、論理エラー率が抑制された後は、回路ボリュームに対してより制御されたスケーリングになります。これらのコストの形は模式的なもので、正確な交差点は物理エラー率、目標とする論理忠実度、具体的なアルゴリズムによって決まります。定性的なポイントは、小さなボリュームでは緩和や検出が適切な選択になり得る一方、回路ボリュームと信頼性の目標により、それらの軽量な手法のコストが高すぎるようになると、訂正が有利になり得るということです。この交差点が、あらゆる優位性の主張が位置する領域を定めます。

近い将来の優位性のデモンストレーションでは、現在のハードウェアで実行できるボリュームでコストを管理可能な範囲に保てるなら、緩和と事後選択が有用です。大規模なフォールトトレラント計算では、厳密な緩和や事後選択による検出だけではオーバーヘッドが法外になり得るため、デコーディングに基づく訂正が中心になります。これらの手法は、QECの連続体に沿って組み合わせることもできます(QEC continuumブログを参照)。

理解度チェック​

上の模式的なモデルでは、PEC、事後選択、およびデコーディングを伴うフォールトトレラントな訂正は、回路ボリューム VVV の関数として質的に異なるコストの形を持ちます。それぞれの形を説明し、各ツールがいつ優位になるかについて何を意味するかを述べてください。

答え

このモデルでは、PECと事後選択のコストはボリュームに対して指数関数的で、PECのサンプリング・オーバーヘッドは ∼ecVp\sim e^{cVp}∼ecVp、事後選択の受理率は ∼e−c′Vp\sim e^{-c'Vp}∼e−c′Vp です。デコーディングを伴うフォールトトレラントな訂正は、代わりに大きな初期のアーキテクチャ上のコスト(符号パッチ、マジック状態ファクトリー、デコーダー、モジュラー・ハードウェア)を支払い、論理エラー率が抑制された後は緩やかに増加します。相対的なコストは交差し得ます。小さな回路では緩和と検出が有利で、深い回路では訂正が有利であり、その交差点があらゆる優位性の主張の領域を定めます。(実際のコストモデルはもっと複雑であり、重要なのは正確な交点ではなく形の違いです。なお、このモデルでのPECと事後選択のコストは VVV に対して一定ではなく、その急増こそが要点であり、訂正は特に VVV に対して指数関数的ではありません。)

「いつ」という問いの現在地​

誠実な結論は、訂正が勝つとか、緩和や検出が勝つということではなく、タスク、正しさの検証方法、リソース予算という次の要因に照らして、各ツールが特定の優位性の主張にどれだけ適しているかを比較検討できる、ということです。第3〜5部のケーススタディは、そのコストの交差点が訂正に有利に動くまで、スペクトルの訂正側の端を押し進める具体的な試みの1つであり、それは今も動き続けています。最新のステップである符号連結は、内側の符号の論理量子ビットを外側の符号のデータスロットに符号化することで、より大きな符号を構築します。これは、ハードウェアではなく内側の符号の論理操作によって非局所性を提供することで、オーバーヘッド・抑制・接続性のトレードオフをさらに一段緩和します。著者らの分析では、288データ量子ビットの2グロス符号よりも少ないスペース・オーバーヘッドで、メモリについてテラクオップ領域に到達すると報告されています(Wills et al., 2026)。大規模なBBアーキテクチャは、依然として主に回路レベルのシミュレーションとアーキテクチャ分析によって裏付けられています。これとは別に、IBMとパートナーは2026年7月30日に量子優位性のデモンストレーションを報告し(量子優位性の発表)、Quantum Advantage Trackerを通じて古典的手法との比較が継続されています。IBMとシカゴ大学による実験は、前のレッスンで紹介した時空間符号の事後選択の手法を用い、実効的なゲートエラーの約 10×10\times10× の削減を報告しました(量子優位性の発表)。その最初の70量子ビットのインスタンスは、後に古典的にシミュレートされ(Manabe et al., 2026)、改訂された実験では76個の物理量子ビットに符号化された64量子ビットの回路が使われています(Martiel et al., 2026)。Starlingの大規模フォールトトレランスのマイルストーンは、依然として2029年の目標です(フォールトトレランス・ロードマップ)。これはLanes et al., 2025が予想していたことと一致しており、優位性は単一のマイルストーンとしてではなく、ますます堅牢になるデモンストレーションの連なりとして到来し、それぞれが最良の古典的ベースラインに対して検証され、公開の場で決着がつけられます。

新しい結果の評価​

エラー処理の戦略を選ぶには、まずタスク、正しさをどのように検証するか、そしてリソースコストの全体を考えます。このレッスンの符号、デコーダー、ハードウェアの例は、エラー訂正がそれらの要件を満たしつつ計算上の優位性を維持できるかを評価するのに役立ちます。緩和と事後選択は、論理回路上を含め、エラー訂正を補完できます(QEC continuumブログ)。

Quantum Advantage Trackerは、候補となる量子計算と最先端の古典的手法とのオープンな比較を支援します。両者が進歩するにつれ、性能比較とリソース見積もりは見直される必要があります。新しい結果ごとに、どの精度が示されているか、どのリソースが数えられているか、比較に利用可能な最良の古典的手法が使われているかを確認してください。エラー処理のワークフローを評価または設計するときは、これらの問いを活用してください。
